# H01 采集完整性检查

实现日期：2026-10-21。适用分支：`collection`。

## 1. 使用方式

点击“开始采集”后即记录原始 ADC。录制时展开采集栏的“各块”菜单，可查看每个预期块的帧数和接收状态，包括始终没有首帧的块。

- 黄色“待复核”：存在超过提醒阈值的时间空缺。
- 红色“不合格”：存在严重时间空缺、整段缺块、只有一帧或记录错误。
- 单块静默时仍继续保存其他块。即使没有下一帧到来，100 ms 刷新定时器也会检查当前等待时间。
- 写盘故障或队列溢出被发现后自动结束本段。串口断开、录制中退出软件同样作为异常结束处理。

结束后，“文件已保存”与“质量合格”分别判断：文件正常写完但严重断流可以是 `complete + fail`。不合格样本不能直接标记有效。点击“作废”会将本次样本整个文件夹移出正式数据目录，放入 `dataset/_trash/<回收编号>/data/`，并从正式索引中移除；原编号不复用，重采使用新编号。通过完整性检查仍需要人工确认动作是否做对。

误操作可通过“恢复删除”选择作废样本，恢复到原路径；不会覆盖同名文件夹。恢复后仍保留 `accepted=false`，不会自动进入有效训练集合。此改动只处理之后点击作废的样本，不会批量移动历史作废数据。

当前预期参与块仍来自固定采集布局。H02 的参与块选择和严格开始前检查、H03 的异步收尾、H05 的崩溃恢复不属于本次实现。

## 2. 判断规则

每块检查三个位置：开始至首帧、相邻帧之间、末帧至录制结束。开头与结尾以关闭数据接纳边界的时间计算，排空磁盘写入队列耗时不算入断流。

配置位置为项目的 `configs/collection_quality.json`，每次点击开始前读取，随后冻结到本段元数据；修改配置影响下一段录制。配置不存在时使用默认值，格式或数值错误时阻止开始并提示原因。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `warning_floor_s` | 0.2 | 提醒阈值下限，秒 |
| `failure_floor_s` | 1.0 | 严重阈值下限，秒 |
| `warning_multiplier` | 5 | 提醒阈值的正常间隔倍数 |
| `failure_multiplier` | 20 | 严重阈值的正常间隔倍数 |
| `min_reference_intervals` | 10 | 使用自适应阈值所需的最少间隔数，最大 128 |
| `reference_window_s` | 5 | 开始前接收参考的回看窗口，秒 |
| `max_events` | 100 | 每条样本最多保存的异常区间明细数 |

正常接收参考 `T` 来自录制开始前近期接收间隔的中位数。采样数不足、数据陈旧、明显成批到达（短间隔低于 1 ms）或间隔波动过大时不使用自适应参考。波动检查采用第 90 百分位不超过第 10 百分位的 5 倍；这些是保守的参考有效性筛选，不代表硬件故障结论。

```text
提醒阈值 W = max(warning_floor_s, warning_multiplier × T)
严重阈值 F = max(failure_floor_s, failure_multiplier × T)
```

没有可靠参考时采用配置的固定下限，同时在最终结果中至少标记为待复核，明确说明原因。不会根据录制过程中的长时间断流自动放宽阈值。默认阈值为试运行值，需要结合实际串口模式和动作时长试采校验。

| 条件 | 最终质量 |
| --- | --- |
| 所有预期块至少两帧，参考可靠，无超阈值空缺和记录故障 | `pass` |
| 存在超过 W 但未超过 F 的空缺，或参考不足/不稳定 | `warn` |
| 存在超过 F 的空缺、某块少于两帧、整段缺块、数据记录异常或异常结束 | `fail` |

恰好等于阈值不升级为异常，比较时有极小浮点容差。两帧只是完整性最低检查，不等于足够训练。无帧时记录整段无数据，不伪造首尾时刻。

## 3. 保存内容与旧数据兼容

新样本 `meta.json` 使用 schema 1.1，增加顶层 `quality_status`，录制初始为 `pending`，结束后为 `pass/warn/fail`。

`quality.integrity` 保存：

- `rule_version=receive_integrity_v1` 和本次冻结的全部规则参数。
- 每块正常间隔参考、参考数量、来源以及实际使用的提醒/严重阈值。
- 每块帧数、首末帧时间、开头空缺、结尾空缺和最大相邻间隔。
- 每块提醒与严重异常次数、块状态及原因。
- 异常区间的块编号、类型、起止秒数、持续秒数及严重程度。
- 全局原因、异常区间总数及 `events_truncated` 标记。

超过明细上限时不继续扩张明细列表，但总次数和最严重状态仍完整累计。实时刷新使用只读快照，不会每刷新一次就重复计数。文件原有的速率、缺块、丢弃行、未写入行和错误字段继续保留。

`index.csv` 在原有七列后追加 `recording_status`、`quality_status`。旧样本没有质量字段时重建索引显示 `unknown`，不修改旧元数据，也不自动宣称其通过检查。旧文件可继续读取；历史质量复核与迁移仍需另外完成。

新样本只有正常结束且没有记录/写盘故障才能得到 `complete`；断连、退出、磁盘故障等为 `incomplete`。底层审核接口同样拒绝把 `incomplete` 或 `quality_status=fail` 设为有效。待复核样本允许人工判断；完整审核说明历史属于后续功能。

本功能不依据 ADC 大小判错，不滤除 0、4095 或梯形空位，不修改原始 CSV 和固定通道映射。主机接收时间不能直接解释为硬件采样时间，本功能报告接收空缺，不提供准确硬件丢帧数量。

## 4. 维护入口与验证

- `collection_quality.py`：独立判定逻辑、冻结规则、有限异常明细与快照。
- `live.py::recording_cadence()`：录制前近期接收间隔参考。
- `dataset.py`：接纳帧更新统计、停止时最终判定、元数据与审核限制。
- `ui/main_window.py`、`ui/collection_bar.py`：实时逐块提示、故障结束与结果展示。
- `tests/test_collection_quality.py`：首尾和中间断流、静默刷新、异常结束、参考冻结、规则验证、审核限制和原始 ADC 保留等回归测试。

实机试采应覆盖正常轻拍/握持/拥抱，以及只断开某一块、拔掉串口后结束等情况，确认当前规则适合实际接收节奏。
