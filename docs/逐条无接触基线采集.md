# 逐条无接触基线采集

更新日期：2026-11-02。适用于 collection 分支的界面采集流程。

对应实现：录制与落盘在 `src/skin_draw/dataset.py`，基线计算在 `src/skin_draw/collection_baseline.py`，波形复核在 `collection_waveform.py` 与 `ui/collection_waveform.py`，连接基线与显示链在 `live.py` / `preprocessing.py`。样本文件格式见 [训练数据采集与存储方案](训练数据采集与存储方案.md)，完整性与接触形态判定见 [H01 采集完整性检查使用说明](H01_采集完整性检查使用说明.md)。

## 这份文档解决什么问题

每条样本录制开始时强制留出 1 秒无接触，用这 1 秒估一条“本条基线”。它承担三件事：

1. **门控动作开始时间。** 界面提示“可以开始动作”之后才允许出现接触；人工标注的接触开始不得早于该时刻。
2. **提供本条内的固定参考。** 为后续离线训练预处理提供可复现的基线，不被录制中期的漂移污染。
3. **冻结当时的判定。** 阈值、逐块统计、结论和提示时刻一起写入 `baseline.json`，供事后审计。

它与热力图使用的“连接基线”不是同一个东西，口径差异见下文。

## 使用流程

1. 连接设备，松开所有皮肤块，等待连接标定完成。归一化须开启（A 或 B），固定布局中每块的有效点都须有可用基线，否则“开始采集”会被拒绝。切换 M3 滤波会清空并重新标定，切换后同样要等标定完成。
2. 选好受试者、场次和动作，点击“开始采集”。此时立即创建样本目录、写 `raw.csv` 表头并写首版 `meta.json`（`recording_status` 为 `recording`），原始数据从第一帧起开始记录。
3. 保持无接触。界面按顺序显示三种状态：
   - `请勿接触 · 基线采集中，剩余 x.x 秒`
   - `请勿接触 · 正在检查基线，等待开始动作提示`：1 秒窗口已收满，后台正在统计
   - 绿色 `可以开始动作 · 本条基线已固定`：此后才可以接触
4. 执行动作，松开皮肤块后点击“结束采集”。点击瞬间关闭接纳边界，剩余数据在后台排空写盘，界面不卡顿。
5. 写盘完成后后台读取完整 `raw.csv` 并画出完整波形。橙色区是前 1 秒基线窗口，提示条会写出“动作提示于 x.xxx 秒发出”。
6. 程序已按接触检测预填起止（首末个超阈值帧），可直接点“确认起止并保存”，或微调后再保存。时间不合法时保存按钮不可用。
7. 点“标记有效”或“作废”。作废会把整条样本移入 `dataset/_trash/`。

两条补充规则：

- **基线不合格会自动结束本条**（`end_reason` 为 `baseline_failed`），原始文件与失败原因保留，不允许标记有效。可作废重采，或暂不标注继续操作；程序不会把后面的按压段当成新基线。
- **波形复核未处理完不能开下一条**：必须先“确认起止并保存”，或点“暂不标注”保留自动检测结果（没有自动结果时仍为 `unlabeled`）。

## 两种基线的口径

| 项目 | 连接基线 | 本条基线 |
|---|---|---|
| 取数位置 | 显示预处理链的当次输出：M3 滤波关闭时为原始值，开启时为滤波值 | 始终是未滤波的原始 ADC |
| 样本数量 | 每有效点收满 270 个样本后取中位数 | 相对时间 `[0, 1)` 秒内的原始帧中位数，约 71～72 帧 |
| 固定时机 | 连接后自动完成，此后固定；切换滤波或重新标定会重置 | 每条开始时重新估计，整条内固定 |
| 保存位置 | `session.json` 的 `calibrations.<calibration_id>` | 样本目录的 `baseline.json` |
| 坐标 | `raw_row_col` | `raw_row_col` |
| 用途 | 热力图显示；作为逐条基线的提前接触参考；接触激活统计 | 本条判据；离线预处理参考 |

三点需要注意：

1. **取数口径随滤波开关变化。** 默认 M3 滤波关闭，两种基线都取原始值，差值只反映采样噪声与时间差；pat002 十块中九块的本条中位数与连接基线相差不超过 10 ADC。开启滤波后连接基线来自滤波输出，与本条基线口径不同，差值会明显变大，判定阈值 100 ADC 必须为这个差异留余量。
2. **参考偏差检查取“最差点”。** 单个离群点会主导结果。例如 pat002 的 BLOCK 3 因一个点偏高 38 ADC 成为该条判定值，其余块均低于 11 ADC，阈值 100 ADC 未触发。
3. **逐条基线不覆盖连接基线，也不改变热力图处理链。** 波形显示的是每块有效点的平均原始 ADC，不是扣基线后的响应。

## 检查规则

规则文件：`configs/collection_baseline.json`，每次开始采集读取一次，并随结果保存为 `policy` 快照。

| 配置项 | 默认值 | 含义 |
|---|---:|---|
| `duration_s` | 1.0 秒 | 本条初始基线窗口，右端不包含 |
| `min_samples` | 每块 20 帧 | 低于此数不能建立本条基线 |
| `max_edge_gap_s` | 0.15 秒 | 首帧距 0 秒、末帧距 1 秒的最大空缺 |
| `max_interval_s` | 0.15 秒 | 基线窗口内相邻帧最大间隔；重复或倒退时间也不通过 |
| `max_spread_counts` | 30 ADC | 每有效点 P95−P5 的上限，取最差点判断 |
| `max_drift_counts` | 20 ADC | 前后各三分之一样本的中位数差绝对值上限 |
| `max_reference_delta_counts` | 100 ADC | 与连接基线的明显偏差阈值，双向检查 |
| `contact_min_frames` | 3 帧 | 任意有效点超过参考偏差阈值的帧数达到此数即疑似接触 |
| `max_samples_per_block` | 2048 帧 | 每块基线缓存上限，超过则判失败，不丢原始文件行 |

判定分组累加，任一条不满足即整条 `failed`，所有原因都写入 `reasons`：

1. **样本与覆盖**：每块样本数达到 `min_samples`，首帧与末帧距窗口边缘不超过 `max_edge_gap_s`，相邻帧间隔不超过 `max_interval_s`。
2. **稳定性**：跨点最大 P95−P5 不超过 30 ADC，前后三分之一中位数漂移不超过 20 ADC。
3. **参考偏离**：逐帧超过 100 ADC 的疑似接触帧数达到 3 帧，或本条中位数与连接基线相差达到 100 ADC。

这些检查只能发现数据不足、不稳定或相对参考的明显偏移，不能证明绝对无接触。例如连接标定时就持续按着皮肤，之后又以同样状态开始采集，程序可能无法识别，因此两个阶段都必须按提示松开皮肤。若确认无接触仍反复提示参考偏差，应重新做连接校准，而不是放宽阈值。

## 保存内容与字段

每条样本包含三个文件：

```text
pat001/
├─ raw.csv        # 前 1 秒基线段 + 动作段，原始值不扣基线、不裁剪
├─ baseline.json  # 判据快照：基线矩阵、窗口、规则、逐块统计、状态与原因
└─ meta.json      # 样本身份、baseline 摘要、质量、人工接触起止、有效性标记
```

### baseline.json

| 字段 | 含义 |
|---|---|
| `schema_version` / `method` | 固定为 `1.0` / `initial_raw_median_v1` |
| `status` | `ready` 或 `failed` |
| `window_start_s` / `window_end_s` / `window_end_exclusive` | 基线窗口与右端是否开区间 |
| `coordinates` | 固定 `raw_row_col`，即硬件原始行列顺序 |
| `frozen_within_trial` | 本条内固定，不随录制推进更新 |
| `reference_calibration_id` | 判定时参考的连接基线编号，指向 `session.json` |
| `policy` | 当次生效的完整阈值快照 |
| `blocks` | 逐块统计：`samples`、`first_time_s`、`last_time_s`、`max_gap_s`、`max_spread_counts`、`max_drift_counts`、`max_median_reference_delta_counts`、`suspected_contact_frames`、`reasons` |
| `baselines` | 逐块基线矩阵，浮点中位数，无效点为 `null` |
| `reasons` | 失败原因汇总，`ready` 时为空 |
| `contact_check` | 固定说明字符串：这些检查不构成无接触的证明 |
| `action_allowed_s` | 界面实际发出动作提示的相对时间，收尾时写入 |

### meta.json 中的摘要

新界面记录的 `meta.json` 为 schema 1.4，`baseline` 是上述文件的摘录：

```json
"baseline": {
  "file": "baseline.json",
  "method": "initial_raw_median_v1",
  "status": "ready",
  "window_start_s": 0.0,
  "window_end_s": 1.0,
  "action_allowed_s": 1.149717,
  "coordinates": "raw_row_col",
  "frozen_within_trial": true,
  "reasons": []
}
```

人工起止单独记在 `annotation`：`status` 为 `auto` 表示录制时按接触检测自动写入（首末个超阈值帧，非真实接触边界），`confirmed` 表示人工确认。自动结果附带 `auto` 子对象记录阈值、块帧数与 `open_at_end`（结束时仍在接触，端点不可信）。重复标注时旧值进入 `annotation_history`。

### 时间与坐标

- 所有时间都相对于本条录制起点，用单调时钟计算，不从界面刷新时间反推。
- `action_allowed_s` 是界面准备发出提示时的相对时间，含统计与调度等待，不是检测到的接触起点。实测在 1.10～1.15 秒之间，比 1.0 秒窗口多出的部分是后台计算与界面定时器延迟。
- `baseline.json` 的 `baselines` 按硬件原始行列保存；`raw.csv` 已按人体方向重排。预处理时必须用布局的 `saved_to_raw_index` 把基线映射到保存顺序，**不能再对 CSV 旋转一次**。
- `baseline.json` 的矩阵与 `session.json` 中对应标定的矩阵都是 `raw_row_col`，可以逐点直接比较。

### 连接基线的追加规则

每次点击“开始采集”都会向 `session.json` 追加一条新的 `calib_00N`，即使内容与上一条完全相同；样本通过 `calibration_id` 引用其中一条，历史条目不会被改写或删除。因此 `session.json` 随样本数线性增长，当前 10 块配置下每条标定约 9 KB，其中各块基线矩阵是主体；块数与点位数越多，单条越大。同一场次内若未重新连接或重新标定，各条标定的数值基本一致。

### 可复算性与定位

- `baselines` 矩阵与 `blocks` 的统计量，都能由 `raw.csv` 前 1 秒加同一份 `policy` 逐位重算，因为 `raw.csv` 未滤波、未裁剪、未丢行。
- 不能复算的只有三项：`policy` 快照（配置文件可被修改）、`action_allowed_s`（界面事件）、以及判定结论本身。
- 因此 `baseline.json` 的定位是**判据快照与交叉校验依据**，不是训练时的基线来源。离线统一处理应从原始数据重算基线，再用这里的结果做一致性校验；两者不一致说明文件被改动或时钟异常。
- `baseline.json` 只在本条收尾时原子写入一次；录制中的 `meta.json` 状态为 `recording`。异常中断、提前停止或计算失败都保留失败状态与原因。失败记录即使含部分候选基线，也不可当作合格基线使用。

## 与其它质量判定的关系

| 判定 | 来源 | 作用 |
|---|---|---|
| `recording_status` | 写盘、队列、缺块、数据异常、基线、结束方式 | `complete` 或 `incomplete`，任一项出问题即为 `incomplete` |
| `end_reason` | 上表首个问题；用户正常停止时为 `user_stop` | 基线失败写作 `baseline_failed` |
| `quality_status` | `quality.integrity` 与 `quality.semantic` 取较严重者 | 完整性或接触形态不合格都不能标有效 |
| `accepted` | 人工标记 | 未完成或 `quality_status` 为 `fail` 时不能标 `true` |

- 基线失败会同时体现在 `recording_status`、`end_reason` 与 `baseline.reasons` 中，三者是同一事实的不同视角。
- `index.csv` 每行带 `recording_status` 与 `quality_status`，便于批量筛选，但它由各 `meta.json` 重建，不是数据源。
- 人工标注只写 `annotation`，不会覆盖上述任何判定。

## 性能与线程边界

- 原始写盘队列入队优先；随后仅将不可变原始矩阵的引用加入有上限的基线缓存。
- 中位数、分位数和漂移检查在独立线程运行，接收线程和界面线程不等待计算。
- 缓存只接收第一秒内的数据，超过窗口的数据不参与本条基线，结果完成后释放缓存。
- 点击结束只关闭接纳边界；排空写盘、基线收尾、JSON 写入和索引刷新都在后台执行，界面线程不 sleep、不 join、不等磁盘。
- 波形预览是有损的（队列满即丢），完整波形始终从已关闭的 `raw.csv` 重读。

## 测试与验证

自动化测试覆盖：持续按压时本条基线固定、下一条重新估计、坐标与掩码、提前接触/波动/缺块/间断/容量不足/提前停止、计算延迟期间原始记录和界面事件继续、失败样本不能标记有效、接触标注不能覆盖基线段。

2026-11-02 复核：`pytest -q` 506 项通过、1 项跳过，耗时 79 秒。

2026-10-27 离屏模拟基准（历史记录，不代表当前状态）：模拟 8 块皮肤、每块 100 Hz、每轮 3 秒，按关闭/开启/开启/关闭实时波形进行 4 轮；每轮 2400 行全部写入、丢行 0，逐条基线均为 `ready`，动作提示在 1.118～1.125 秒发出；热力图提交耗时 P95 为 1.65～3.40 ms，提交间隔 P95 为 17.0～19.6 ms。

真实传感器的检查通过率与可见刷新效果仍需实机试采确认；上述数字都不是关闭逐条基线的前后对照。
