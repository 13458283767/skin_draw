# 二进制 v0.5 解析说明

依据用户提供的《二进制数据帧协议_v0.5.md》（2026-09-15 草案）更新。本文描述当前上位机实现；文档中的板端故障原因与清缓冲效果尚未通过本次硬件实测验证。

## 1. 帧格式

```text
AA | ID | M | N | ADC 大端 uint16，逐行排列 | 0A
 1    1    1   1            2×M×N              1 字节
总长度：5 + 2×M×N
```

- ID：1～16；最终使用 1～14 不影响解析。
- 正常帧 M、N：各 1～16，ADC：0～4095。没有传感器的 0 原样保留。
- M=N=0：5 字节未就绪回复，检查 0A 后记录设备 ID，不创建矩阵，不计校准帧。
- 仅 M 或 N 为 0：拒绝。文档预留的状态码帧本版不实现。
- 示例：5×3 为 35 字节，7×3 为 47 字节，10×5 为 105 字节，13×5 为 135 字节，16×16 为 517 字节。

## 2. 增量解析流程

1. 接收任意长度的串口字节片段，追加到解析缓冲区；不使用 readline 分割二进制数据。
2. 找到潜在帧头 AA，收齐 ID/M/N 后验证字段，计算完整长度。
3. 等待声明长度的数据。此期间负载低字节的 AA、0A 都是 ADC 内容，不能当新帧头或帧尾。
4. 检查 ADC 高字节不超过 0F；已能确认越界时立即拒绝候选帧，不必等待错误的长度字段超时。
5. 收齐后，最后一个字节必须为 0A。帧尾校验不可关闭。
6. 正常帧将负载按大端 uint16 解码为 M 行 N 列，生成原始 Block；未就绪帧只更新状态。
7. 消费完整帧，继续处理同一缓冲区中的下一帧，支持连续多块粘包及任意边界拆包。
8. 字段、ADC 或帧尾非法：候选帧不输出，记录原因，从后续潜在帧头重新同步，而非清空整个接收缓冲，尽量保留紧随的好帧。
9. 候选帧从首次识别帧头起超过 250 ms 仍不完整：记录残帧超时并重同步。空读也会推进超时检查。

250 ms 是未收齐时的保护上限，不是每帧等待时间。完整帧立即输出。115200/8N1 下最大帧需要约 45 ms，仅设 5 ms 的固定完整帧超时不适合所有尺寸。

## 3. 明文兼容和轮询

- “自动识别”只区分明文 BLOCK 与 v0.5 二进制，两种格式可在完整帧边界交替到达。
- 仍可选择“仅明文 BLOCK”或“仅二进制 v0.5”。明文 END 的原有兼容逻辑保留。
- 若电脑发起轮询，命令仍是 ASCII `hello num <ID>\r\n`。接收层解析合法 ID，轮询层只向绘图/校准交付本次目标 ID 的数据；其他 ID 的回复记录并忽略。
- 未就绪设备仍保留在已检测设备列表，下一轮再查询。坏帧不会被当作一次有效校准。
- 初次检测 ID 1～16，之后按升序查询已响应设备；连接 1～14 时即为 1→14 循环。
- 若板端已自行轮询并转发，上位机使用连续接收模式，收到哪块就更新哪块，不等待全身一轮凑齐。

## 4. 界面、日志和现有数据处理

- 移除旧“校验二进制 CRC”选项；协议下拉框显示 v0.5。
- 连接日志记录二进制版本 0.5 和固定帧尾 0x0A。
- 解析日志区分 ID/尺寸错误、ADC 高字节越界、帧尾错误、残帧超时，保留错误计数与限频 HEX 片段。
- 前 30 个有效校准帧、整行突变过滤、实时绘图、皮肤旋转/镜像/拖动沿用原有逻辑。
- 协议层的原始矩阵不旋转、不删零、不覆盖跳点；显示方向和过滤仍由后续模块处理。

## 5. 版本与能力边界

- 本次将二进制解析切换至 v0.5，不保留 v0.3/v0.4 两字节 CRC 的运行选项。设备节点及转发主机必须使用匹配的长度与尾字节。
- 协议没有版本字段，不能可靠地自动区分旧 CRC 帧与新 LF 帧。旧帧若 CRC 首字节碰巧为 0A，也可能被误判为新帧，不能以偶尔能显示作为版本正确的依据。
- LF 尾标记不是 CRC：合法范围内的 ADC 字节误码可能通过校验，失步后的伪帧也不能完全排除。行过滤是显示处理规则，不是传输校验。
- 本版没有设备帧序号、轮次编号或采样时间戳；软件不推导声称可靠的硬件轮次，也不能仅凭当前帧判断精确丢包数。
- 本次只更新上位机，未修改或烧录 MCU 固件，未新增 H5/CSV 训练数据采集功能。

## 6. 验证覆盖

测试使用文档原始 HEX 示例、完整和损坏的未就绪帧、0/4095 范围边界、ADC 中 AA/0A、错误帧尾和缺尾、插入/删除字节后的恢复、残帧超时、最大帧按 115200 到达、14 块不同尺寸数据的所有双段切分点、14 块模拟轮询的 ID 匹配、校准与界面更新，以及错误日志分类。

这些是协议与模拟串口验证；实际暂停是否消失，需设备与转发端采用 v0.5 后通过真实连接日志确认。
