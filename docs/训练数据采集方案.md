# SkinDraw 训练数据采集方案

状态：设计提案，尚未实现采集录制功能。基于当前项目代码核对。

暂按触摸、按压、滑动等动作分类设计；物体或材质分类可以复用数据结构，连续压力或位置预测需增加对应真值。下述时长、样本数为初期实验建议，不代表已验证的最佳参数。

用户补充的当前配置：连接 5 块皮肤，每块约 18 帧/秒；此速率为用户提供，尚未独立实测。每块行列数及目标识别任务待确定。方案按此配置设计。

## 1. 建议采用的方案

保存“原始 ADC 数值矩阵 + 接收时间 + 基线 + 标签 + 实验信息”，录制主文件使用 HDF5（.h5），训练时可直接读取，也可离线导出按样本组织的 NPZ（.npz）。CSV 用来浏览样本目录，JSON 用来保存类别和实验配置，PNG 只用作预览。

网络最终接收数值张量。文件后缀本身不会提高识别率；完整的时序、准确标签、稳定的传感器映射和独立测试数据更重要。

HDF5 支持多维数组、切片读取、可扩展数据集和压缩，适合持续录制；NPZ 能把多个具名数组保存到一个压缩文件，适合结束采集后按样本导出。依据：[h5py 官方文档](https://docs.h5py.org/en/stable/high/dataset.html)、[NumPy 官方文档](https://numpy.org/doc/stable/reference/generated/numpy.savez_compressed.html)。

| 文件 | 用途 | 是否作为原始训练数据主文件 |
|---|---|---|
| .h5 | 持续追加多块矩阵、时间戳、基线、质量标记和标签 | 推荐 |
| .npz | 将一个已切好的动作样本及其掩码打包，方便 Python 训练 | 可作为训练派生文件 |
| .csv | 查看样本编号、类别、次数、时长、质量和数据集划分 | 辅助 |
| .json | 保存类别表、实验设置、布局和预处理版本 | 辅助 |
| .png | 人工检查热力图 | 不作为主数据 |
| .bin | 可选的串口字节流排障记录，需另存接收块时间与偏移 | 不直接作为网络输入 |

## 2. 当前软件对应的接入位置

- `SerialAcquisition.on_block` 逐个交付有效的单块矩阵，进入 `SerialWorker._receive_block`。
- `LiveBuffer.receive` 执行预处理（M3 滤波、慢基线、归一化）和显示值计算。
- 界面取各块最新快照，会跳过中间显示状态；不能从界面刷新回调或 PNG 导出位置录制训练数据。
- 当前 M3 高位滑窗均值滤波会平滑显示输出：零散低值跳变被自动剔除，真实按压约 30 帧后跟随；显示矩阵不是原始矩阵，不能仅保存滤波输出。
- 当前协议没有设备采样时间、硬件帧序号或 CRC。接收时间不是精确采样时间，软件编号不能证明硬件没有丢帧。

建议在 `_receive_block` 入口生成一次高分辨率接收时间和软件事件序号，由一次处理产生“原始矩阵、滤波输出、基线版本”等不可变记录，交给独立写盘队列。显示继续使用现有最新快照机制；滤波和基线只计算一次。

这里的“有效矩阵”指现有接收流程接受并交付的矩阵。解析失败、轮询非目标回复等另记诊断事件，不伪装成有效样本；若要保留全部串口字节，应在底层读取入口另加可选字节流记录。

## 3. 建议的使用流程

1. 新建采集会话：选择保存目录、任务名称、操作者/受试者代号、设备和实验批次。
2. 检测实际皮肤块、核对每块尺寸和物理安装位置，完成无接触基线校准。
3. 选择类别，例如 `no_contact`、`press`、`tap`、`slide_left`、`slide_right`。
4. 选择手动结束或定时录制，倒计时后执行一次动作，结束后自动编号保存。
5. 显示本次时长、各块接收帧数、异常比例、最长接收间隔，允许标记废弃或重采。
6. 重复下一次动作，保留明确的“无接触”样本，避免所有无接触状态都被判为某一种动作。
7. 结束会话，关闭数据文件，更新索引并允许回放。

界面最小控件：保存目录、会话信息、类别选择、新增类别、录制时长、开始/停止、本类次数、作废上次、打开目录。录制状态同时显示“实际已写入帧数”，不能只显示计时器。

一次试验包括动作前静置、动作过程、动作后恢复，建议先尝试 3–5 秒并结合实际动作时长调整。标签必须区分“整次试验类别”和“动作发生区间”：例如一条 press 试验内的静置部分不应全部自动标为正在按压。第一版支持人工标记动作起止；自动阈值切段放到后续，且必须能人工修正。

## 4. 数据目录与主文件结构

```text
dataset/
  classes.json                  # 类别 ID、名称、定义和版本
  samples.csv                   # 跨会话样本索引，可从主文件重建
  sessions/
    20260924_153000_<唯一ID>/
      data.h5                   # 本会话原始数据及权威标签
      metadata.json             # 易读的会话信息摘要
      preview.png               # 可选
  exports/
    preprocess_v001/            # 可重新生成的训练文件
      trial_<唯一ID>.npz
      split.json                # 按会话/人员/试验分组的划分
```

每个会话固定设备集合、尺寸、基线版本、受压方向和物理布局。重新校准、重连、增减块或尺寸变化时结束当前段，创建新会话/新段，禁止把两种基线或形状悄悄拼在同一数组里。第一版直接结束会话并提示重新准备。

HDF5 建议逻辑结构：

```text
data.h5
  attributes: schema_version, session_id, started_at_utc,
              clock_type, time_origin, software_version, completion_status
  /metadata/json
  /classes/json
  /layout/json
  /blocks/block_01/
      raw_adc             uint16   [N1, rows, cols]
      host_time_ns        int64    [N1]
      event_index         uint64   [N1]
      rejected_rows       bool     [N1, rows]
      calibration_used    bool     [N1]
      phase               uint8    [N1]
  /blocks/block_02/...
  /calibration/block_01/
      baseline            float64  [rows, cols]
      source_event_index  uint64   [30]
  /trials/
      trial_id, class_id, start_ns, end_ns,
      action_start_ns, action_end_ns, quality_status, notes
  /events/
      time_ns, event_type, detail_json
```

字段约定：

- `N1`、`N2` 为各块独立的接收数量，可以不同；原始存储阶段不凑成所谓“全身同步帧”。
- `host_time_ns` 为相对会话起点的主机接收时间，使用同一 `perf_counter_ns` 时钟；纳秒是保存单位，不代表纳秒级采样精度。批量到达的报文也不能据此恢复真实采样间隔。
- `event_index` 是本软件交付顺序，从会话内统一计数，用于审计，不是硬件帧号。
- `rejected_rows=True` 表示当前显示过滤器拒绝了这一行；表示规则命中，不能直接认定为硬件坏点。
- `phase` 区分校准、待机、正式试验等。会话在校准前建立，可保留参与基线计算的全部原始校准数据；正式试验须等所需块基线就绪。
- 时间区间统一采用 `[start_ns, end_ns)`；未知动作边界使用明确缺失标记，不能假填 0。
- 无接触的类别 ID 与“未标注”状态分开，类别 ID 一旦使用不重排。
- `/trials` 中保存权威标签；CSV 为导出索引，避免两处编辑导致标签不一致。
- 保存串口设置、解析协议、过滤阈值和算法版本、受压方向、基线算法、设备代号、安装批次、对象/材质及实验条件。没有测量的字段标为未知。
- 布局记录 BLOCK ID、原始行列、实际坐标或邻接关系及单位、旋转镜像。屏幕拖动坐标仅属显示配置，不能冒充真实物理坐标。

## 5. 原始数值如何变成网络输入

以受压后 ADC 减小为例，默认先保留有符号响应：

```text
delta = baseline - raw_adc.astype(float32)
```

先转浮点再相减，避免无符号整数下溢。原始记录不做裁剪；现有显示用的 `max(0, delta)`、固定色阶 0–1000 和颜色映射不作为不可逆的数据保存步骤。基线原值以 float64 留档，训练输入转换为 float32。

离线处理顺序：读取原始记录 → 按标签选择试验 → 根据各块时间轴对齐 → 产生缺失/异常掩码 → 基线相减 → 按训练集统计量归一化 → 形成输入张量。

对齐时应明确目标时间网格和允许的最大样本年龄。第一版可采用最近一次已到达值并附带 `age_ms`，超过允许时差则置为缺失。补值不增加真实采样信息；长缺口不能通过重复旧值制造出完整动作。缺失输入可在归一化后填 0，同时保留掩码，让网络区分“没有测量”和“无接触”。

同尺寸多块的约定：

```text
单个动作 X: [T, K, H, W]          # 时间、皮肤块、行、列
批量输入 X: [B, T, K, H, W]       # B 为训练批量
目标 y:     一个类别 ID
mask:       [T, K, H, W]
age_ms:     [T, K]
```

该布局是本项目的数据约定，实际模型按其要求转置。例如静态分类可取 `[B,K,H,W]`；时序模型保留 T 维。不同块尺寸不一致时，可补齐并保存空间掩码；如果实际皮肤是不规则分布，可导出 `[T,P]` 与真实坐标/邻接关系。不要为了生成彩色图片而拉伸或虚构传感器位置。

单条 NPZ 建议包含 `x`、`y`、`mask`、`age_ms`、`time_s`、`block_ids`、`trial_id`、`session_id`、`preprocess_version`。只保存数值/固定字符串数组，不使用 Python object 数组；主文件保留完整原始信息，NPZ 可以删除重建。

不在任务尚未确定时固定网络架构。动作分类需要时序，静态接触形状可先用单帧或稳定片段；若预测牛顿/千帕或真实坐标，必须另采集同步的力计/压力标定或位置真值。现有 ΔADC 不是物理压力标签。

## 6. 按当前 5 块、每块约 18 帧/秒设计

按用户提供的当前接收速率估算：

| 指标 | 估算值 |
|---|---|
| 连接块数 | 5 |
| 每块接收速率 | 约 18 帧/秒 |
| 每块平均帧间隔 | 约 55.6 ms |
| 全部块合计 | 约 90 块帧/秒 |
| 一次录制 3 秒 | 每块约 54 帧，合计约 270 块帧 |
| 一次录制 5 秒 | 每块约 90 帧，合计约 450 块帧 |

90 块帧/秒不等于全身同步更新 90 次/秒。各块仍独立保存时间戳和矩阵，训练导出时再对齐。接收速率也不直接证明硬件采样时刻及同步精度。

第一版保留每份新到达数据，不主动降采样。可先采用 3–5 秒试验窗口进行慢速按压、保持、释放和滑动的先导采集，通过回放确认动作是否清晰可辨。快速敲击等短事件可能只有少数观测，是否足够需结合动作持续时间和实际间隔判断。

若 5 块具有相同行列数 H、W，3 秒数据在对齐至 18 Hz 后可组织为约 `[54, 5, H, W]`；5 秒为约 `[90, 5, H, W]`。这是离线对齐后的形状示例，不保证每块实际恰好收到这些帧。对齐必须同时输出缺失掩码和样本年龄。

早先“14 块、每块 16×16、115200 波特率下约 1.6 帧/秒”的计算属于另一种假设配置，不用于描述当前系统。存储量和链路核算应以当前实际行列数、协议和串口参数为准。

## 7. 写盘可靠性与质量控制

- 独立写盘线程独占 HDF5 文件；接收线程投递不可变记录，不等待磁盘写入。
- 队列按记录数或字节数设置上限，容量按实测速率和允许的磁盘停顿配置。队列满、磁盘满或写盘异常时明确停止录制并标记失败，保留已写入部分；禁止静默丢弃后仍显示采集成功。
- 使用分块可扩展数据集批量追加。首版可选择无损压缩或不压缩，通过真实采集压测决定，不预先承诺压缩率。
- 定期 flush，例如每秒一次；正常结束时排空队列、关闭文件、写入完成状态，再把 `.partial.h5` 重命名为 `.h5`。只有关闭验证成功才展示录制完成。
- flush 和改名不能保证突然断电时完全可恢复；较长会话滚动分文件，启动后识别未完成文件并尝试恢复，无法验证的部分不得当作正常样本。
- 记录各块帧数、间隔分布、异常行比例、解析错误、断连、录制队列溢出和最终写入数量。无硬件帧号时只报告接收间隔异常及已知软件丢弃数，不报告无法证实的精确硬件丢包率。
- 单次试验至少检查所需块是否有足够观测、动作是否覆盖完整、是否跨基线或配置变更。质量阈值应在先导实验后确定。
- 模拟数据必须明确隔离标记，默认不进入真实实验训练集。

## 8. 训练集采集与划分

先用 3–5 个明确类别，每类采集约 30–50 次独立试验，作为验证流程和可分性的先导数据。覆盖不同位置、力度、速度，并随机交错类别顺序，减少按采集时间或漂移区分类别的风险。之后再按学习曲线和错误类型增加数据；不能把先导数量当作足够训练的保证。

切分训练/验证/测试时，先按受试者、会话或完整试验分组，再切时间窗；比例可从 70%/15%/15% 起步，并保证各组中类别分布合理。若目标是泛化到新人，按人员划分；若目标是新对象，按对象划分。同一次动作产生的相邻帧和重叠窗口不得分散到训练与测试中。归一化参数只从训练集拟合。

## 9. 建议的落地顺序与验收

第一阶段：逐帧原始记录、HDF5 写盘、标签和起止时间、元信息/基线快照、录制界面、失败状态。拟新增 `recording.py`、`dataset_schema.py` 和录制面板，在现有 serial_worker/live 流程增加记录分支，并增加 `h5py` 依赖。

第二阶段：历史回放、质量报告、人工修订动作区间、CSV 索引、NPZ 导出和读取示例。

第三阶段：根据实际任务增加自动触发、预录缓冲、外部真值同步以及模型训练/推理入口。

关键验收：

1. 回放数据的原始 ADC 与输入完全一致，正常结束后接收与写入数量相符。
2. 界面暂停刷新或被遮挡不影响记录；异常行原值仍在，且标记正确。
3. 多块异步到达、不同尺寸、断连、校准变更、队列满和磁盘失败都有明确结果。
4. 边界附近帧按同一时间轴归入试验，不因界面回调延迟错标。
5. 主文件独立包含训练所需基线、类别和布局，导出结果能追溯到原始会话和试验。
6. 使用真实硬件完成一轮采集、回放和数据加载，核实采样速度适合目标动作后再扩大数据规模。
