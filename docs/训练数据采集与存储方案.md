# SkinDraw 训练数据采集与存储方案

日期：2026-11-17
状态：`collection` 分支已实现采集布局固定、动作录制、逐条无接触基线、接触判定与自动标注、样本回收以及样本清单重建。本文按**当前代码实际行为**编写，作为采集、复查与训练读取的统一依据；文中数字（10 块、50 列、`skin_layout_v5`、`actions_v3`）是当前配置，不是永久约定。

原始数据采用 **CSV**，样本与场次信息采用 **JSON**，传感器布局与有效点位掩码采用**全数据集共享的版本化 JSON**。

## 1. 已确定的选择

| 项目 | 当前方案 |
|---|---|
| 样本组织 | 受试者 → 采集场次 → 动作 → 本次动作样本 |
| 样本粒度 | 一次录制 = 一次完整动作尝试及前后短暂无接触阶段 |
| 每个样本目录 | `raw.csv` + `meta.json` + `baseline.json` |
| 原始数据 | 保存硬件返回的完整 ADC，保存前不滤波、不归一化、不按数值范围删除 |
| CSV 行含义 | 某一块皮肤新收到的一帧，**不代表全部皮肤同步的一帧** |
| 皮肤块编号 | 固定使用硬件编号，不因连接顺序或缺块重新编号 |
| 时间 | 每条记录保存相对本次录制起点的上位机接收时间 |
| 坐标系 | 按人体方向重排后按行优先展开，保存可逆通道映射与同方向点位掩码 |
| 全局掩码 | 只保存一份，样本通过 `layout_id` 引用 |
| 动作类别 | 全数据集共享固定编号，样本通过 `labels_id` 引用并内嵌动作全字段 |
| 基线 | 两份：场次级连接标定快照（`calibration_id`）与逐条 1 秒无接触基线（`baseline.json`） |
| 训练使用 | 训练前读取 CSV、按 `block_id` 分组、按时间对齐、去重后切窗 |

## 2. 目录结构

```text
dataset/
├─ labels.json                     # 动作类别表（当前 actions_v3）
├─ skin_layout_v5.json             # 被引用的布局版本副本
├─ index.csv                       # 自动生成的样本清单，可重建
├─ _trash/                         # 作废与删除的回收区，不参与训练
└─ student01/
   └─ session_20261117_01/
      ├─ session.json              # 场次设置、协议、标定记录
      └─ pat/
         ├─ pat001/
         │  ├─ raw.csv
         │  ├─ meta.json
         │  └─ baseline.json
         └─ pat002/ ...
```

- 同一受试者隔天采集、重新安装皮肤或实验条件明显变化时，建立新场次。
- 次数编号在同一场次、同一动作下自动递增，三位起补零，超过 999 继续使用 `pat1000`。
- 已存在的样本目录不覆盖；作废重采使用新编号，回收中的编号同样不被复用。
- 点击"作废"会把整个样本目录移入 `dataset/_trash/<32位编号>/data/` 并写入 `deleted.json`，同时重建索引；"恢复删除"按原路径还原，不覆盖同名目录。
- 数据集应整体保存和复制，使全局配置、场次信息与样本始终配套。

## 3. 原始文件 raw.csv

### 3.1 列定义

UTF-8、英文逗号分隔、小数点用 `.`，首行为列名。

| 列 | 含义 | 规则 |
|---|---|---|
| `record_index` | 本次录制的记录序号 | 从 0 开始，每保存一条记录加 1 |
| `time_s` | 相对本次录制起点的接收时间，秒 | 单调时钟计算，输出 6 位小数 |
| `block_id` | 皮肤块编号 | 与硬件编号、全局布局一致 |
| `adc_000` 至 `adc_NNN` | 该块原始 ADC | 按固定人体方向重排后行优先展开，数值不变 |

- 列数在本场次内固定为"该场次布局中最大块的点数"（当前为 50），点数较少的块在行尾留空，**不填 0**。
- 时间记录的是上位机收到该块的时刻，不是硬件采样时刻。
- 6 位小数只是格式约定，不代表微秒级精度。
- `record_index` 是软件编号，不能据此断言硬件没有丢帧。
- 行按接收交付顺序写入；不同块帧数可以不同，同一块内时间不应倒退。
- 首条数据不强制为 0 秒，保留它相对录制起点的实际时间。

### 3.2 示例

以下用两块演示，假设本场次最大块点数为 6：

```csv
record_index,time_s,block_id,adc_000,adc_001,adc_002,adc_003,adc_004,adc_005
0,0.003000,1,2048,2050,2047,2052,,
1,0.014200,2,2039,2041,2040,2045,2049,2051
2,0.017600,1,2046,2049,2050,2051,,
```

### 3.3 矩阵展开规则

先按固定布局旋转／镜像，再从左到右、从上到下展开。对重排列数为 `cols` 的块，索引关系为 `k = row × cols + col`（行列下标从 0 开始）；恢复时只读取该块前 `rows × cols` 个值。

布局中的 `saved_to_raw_index` 记录保存位置对应的硬件原始扁平索引，覆盖全部原始位置且无重复，可完整还原串口顺序。旋转 90°/270° 后行列互换，`raw_rows/raw_cols` 始终记录硬件原始尺寸。

### 3.4 三种位置与缺失情况

1. **硬件返回了数值但该位置没有真实传感器**：原值保留（可能是 0），由全局点位掩码排除。
2. **该块点数少于 CSV 统一列数**：尾部留空，不补 0。
3. **某块某一帧未收到**：不编造记录、不重复上一帧冒充新数据，在训练对齐阶段按时间缺口处理。

ADC 用 `uint16` 表示并校验 0～4095。不能把常见静态读数范围（约 1800～2500）当作保存过滤条件。

## 4. 全局布局与有效点位掩码

所有样本共享一份版本化的 `skin_layout_vN.json`，样本通过 `layout_id` 引用；首次录制时自动复制到数据集根目录，保证数据集可独立读取。

```json
{
  "schema_version": "1.1",
  "layout_id": "skin_layout_v5",
  "coordinates": "body_oriented_row_col",
  "flatten_order": "row_major",
  "placement_mode": "body",
  "view_positions": {"3": {"x": 20.27, "y": 9.77}},
  "blocks": {
    "3": {
      "raw_rows": 7, "raw_cols": 3,
      "rows": 3, "cols": 7,
      "orientation": {"rotation": 270, "flip_x": true, "flip_y": false},
      "saved_to_raw_index": [[0, 3, 6, 9, 12, 15, 18], "..."],
      "raw_valid_mask": [["..."], "..."],
      "valid_mask": [["..."], "..."]
    }
  }
}
```

- `view_positions` 只决定绘图区摆放，不代表物理坐标，不影响 ADC 排列。
- `raw_valid_mask` 是硬件原始行列坐标，`valid_mask` 是重排后坐标；读取时两者都要校验。
- 读取时核对 `layout_id`、索引、尺寸与两份掩码的一致性；损坏配置直接报错，不静默重建。
- 已用于采集的版本不得覆盖。更换皮肤、接线、通道顺序或点位时保存为新版本（`skin_layout_v6.json`），旧样本继续引用旧版本。
- 保存布局时合并当前观察到的块，并保留此前已配置但本次未连接的块。

## 5. 动作类别 labels.json

```json
{
  "schema_version": "1.0",
  "labels_id": "actions_v3",
  "classes": [
    {"id": 0, "name": "pat",   "display_name": "轻拍", "definition": "轻拍机器人手臂或肩部后离开",       "contact_features": "短暂、局部接触"},
    {"id": 1, "name": "grasp", "display_name": "握持", "definition": "握住机器人的手或前臂，保持后松开",   "contact_features": "持续、局部接触"},
    {"id": 2, "name": "hug",   "display_name": "拥抱", "definition": "双臂环抱机器人，保持后松开",         "contact_features": "多个区域的持续接触，取决于传感器覆盖"},
    {"id": 3, "name": "press", "display_name": "推压", "definition": "手掌贴住目标块持续前推，力由轻到重，不离开皮肤", "contact_features": "单区域、持续、力度递增"}
  ]
}
```

- 动作编号全数据集固定，不随界面排序变化。
- 首次录制时写入数据集根目录；已存在且内容不同则直接报错，必须另建数据集。
- 训练合并数据时必须结合 `labels_id` 解释编号，不能只按编号合并。
- 每条样本的 `meta.json` 内嵌完整的动作字段，因此即使类别表丢失，历史标签语义仍可读。

## 6. 场次信息 session.json

首次录制时创建，之后每次录制校验一致性（布局、类别表、ADC 列数、预期块集合任一不同即拒绝开始，要求新建场次）。

| 字段 | 含义 |
|---|---|
| `schema_version` / `subject_id` / `session_id` | 身份与格式版本 |
| `operator_id` / `notes` | 操作人员与备注，当前界面不填写，留空 |
| `started_at` | 场次开始时间（带时区） |
| `software` | 软件名称与版本 |
| `protocol` | 传输方式、端口、波特率、**界面选择值**的接收模式与数据格式 |
| `layout_id` / `labels_id` | 引用的布局与类别表版本 |
| `max_adc_columns` | 本场次 CSV 的 ADC 列数 |
| `expected_block_ids` | 预期参与采集的块编号（来自固定布局） |
| `skin` | 皮肤配置块、安装状态、实验条件（当前留空） |
| `calibrations` | 每次标定一份快照，编号 `calib_001` 起 |

标定快照字段：`calibration_id`、`captured_at`、`method`（`runtime_fixed_baseline_snapshot`）、`coordinates`（`raw_row_col`）、`baseline_mode`（`calib`）、`calib_samples`、`confirmed_bad_points`、`baselines`（各块原始行列矩阵，不可用点写 `null`）。

说明：

- 快照记录的是"该样本录制开始时正在生效的基线"，不是每条重新标定。
- 每次开始录制都会新建一个快照编号并追加，因此同一代基线可能出现多份内容相同的副本；训练侧应以内容判断是否同源，而不是只看编号。
- `protocol` 记录的是界面选择值（`auto`），实际生效的轮询／连续接收并未单独落盘。
- `operator_id`、`skin.installation`、`skin.conditions` 目前为空，实验条件需另行记录。

## 7. 样本信息 meta.json

当前 schema 为 `1.4`（启用逐条基线时）。

| 字段 | 含义 |
|---|---|
| `schema_version` | `1.4` |
| `subject_id` / `session_id` / `trial_id` | 身份 |
| `layout_id` / `labels_id` / `calibration_id` | 引用的全局配置与标定快照 |
| `action` | 动作 `id`/`name`/`display_name`/`definition`/`contact_features` |
| `data_file` | 固定为 `raw.csv` |
| `started_at` / `ended_at` / `duration_s` | 录制起止与时长（单调时钟） |
| `time_reference` | `host_receive_seconds_since_recording_start` |
| `adc_dtype` | `uint16` |
| `coordinates` / `flatten_order` | `body_oriented_row_col` / `row_major` |
| `max_adc_columns` | 本场次固定列数 |
| `expected_block_ids` | 预期参与的块 |
| `annotation` | 动作起止与来源（见下） |
| `annotation_history` | 被覆盖的历次标注（自动→人工留痕） |
| `recording_status` | `recording` / `complete` / `incomplete` |
| `quality_status` | `pending` / `pass` / `warn` / `fail` |
| `end_reason` | 停止原因，如 `user_stop`、`disconnect`、`write_error`、`baseline_failed` |
| `accepted` / `reject_reason` / `accepted_at` | 人工判定，初始为 `null` |
| `primary_block` / `region_set` / `region_count` | 主接触块与区域集合 |
| `activation` | 接触检测摘要（见第 8 节） |
| `summary` | `records`（真正写入行数）与 `frames_by_block` |
| `quality` | 完整性与统计明细（见第 11 节） |
| `baseline` | 逐条基线摘要（见第 9 节） |
| `notes` | 固定说明：原始 ADC 未滤波、未扣基线 |

标注对象：

```json
"annotation": {
  "scope": "trial",
  "action_start_s": 2.373318,
  "action_end_s": 3.037196,
  "status": "confirmed",
  "source": "manual",
  "updated_at": "2026-11-17T..."
}
```

- 录制结束时按接触检测写入初值（`status=auto`，`source=contact_activation_v1`，并带 `auto` 明细）。
- 人工确认后变为 `confirmed`、`source=manual`，原值进入 `annotation_history`。
- 两者都没有时保留 `null` 与 `status=unlabeled`。
- 自动区间是"可测响应区间"，不等于真实皮肤接触区间；端点受阈值与拖尾影响。
- 人工标注必须满足 `0 ≤ start < end ≤ duration_s`，且不早于本条"可以开始动作"的提示时刻。

## 8. 逐条无接触基线 baseline.json

每次录制开头采集 1 秒（`duration_s=1.0`，至少 20 个样本）原始 ADC，取逐点中位数作为本条基线，然后冻结。

```json
{
  "schema_version": "1.0",
  "method": "initial_raw_median_v1",
  "status": "ready",
  "window_start_s": 0.0,
  "window_end_s": 1.0,
  "window_end_exclusive": true,
  "coordinates": "raw_row_col",
  "frozen_within_trial": true,
  "reference_calibration_id": "calib_001",
  "action_allowed_s": 1.14,
  "policy": { "max_spread_counts": 30, "max_drift_counts": 20, "max_reference_delta_counts": 100 },
  "blocks": {"3": {"samples": 72, "max_gap_s": 0.025, "max_spread_counts": 7.9, "suspected_contact_frames": 0, "reasons": []}},
  "baselines": {"3": [[2442.0, 2476.0, 2453.0], "..."]},
  "reasons": [],
  "contact_check": "stability_and_startup_reference_not_proof_of_no_contact"
}
```

判据（任一不满足则整条 `status=failed`，录制随即结束并标 `incomplete`）：

| 项目 | 阈值 | 含义 |
|---|---|---|
| 样本数 | ≥20 | 不足判失败 |
| 窗口覆盖 | 首尾空缺 <0.15 s | 断流 |
| 间隔 | ≤0.15 s，且不得重复或倒退 | 接收间断 |
| 波动（p95−p5） | ≤30 LSB | 疑似接触 |
| 漂移（首尾 1/3 中位数差） | ≤20 LSB | 缓慢滑动 |
| 与连接标定偏差 | <100 LSB，且接触帧 <3 | 提前接触 |

- `baselines` 使用**原始行列坐标**，训练时要按同一布局映射变换后再相减。
- 该文件的定位是"判据快照与交叉校验依据"，训练用的基线建议从 raw 重新计算，再用这里的结果校验一致性。

### 8.1 连接标定的无接触闸门

连接后 3 秒（每个有效点位 270 个样本）建立显示与录制用的运行基线，固定前先过闸门：

| 条件 | 处理 | 界面 |
|---|---|---|
| 波动 >30 LSB | 本批作废、重新收集 | "标定未通过 · BLOCK xx 行r列c 标定窗口波动 N LSB…" |
| 漂移 >20 LSB | 同上 | "…标定窗口漂移 N LSB…" |
| 连续 3 次不合格 | 停止自动重试 | 提示确认无接触后点"重置滤波与基线" |
| 新基线偏离上一代 >100 LSB | **只提示，不阻断** | "自动标定完成 · 基线已固定 · 新基线偏离上一代 N LSB…" |

最后一项只提示，是因为用户主动重新标定常伴随重新贴附，直接拒绝会强迫重复操作。阻断后再次重置视为强制重来，会清空上一代参考。

## 9. 采集流程

```text
连接硬件 → 保持无接触，等待自动标定（270 样本/点，约 3 秒，含闸门）
→ 保存并固定采集布局（方向、镜像、有效点位）
→ 选择受试者 / 场次 / 动作
→ 开始采集：写 session.json / labels.json / 布局副本 → 保存标定快照
            → 写 raw.csv 表头与 recording 状态 meta
            → 采集前 1 秒逐条无接触基线（不合格则中止）
            → 显示"可以开始动作"，记录提示时刻
→ 执行一次动作 → 结束采集
→ 关闭接收边界 → 排空写盘 → 写 baseline.json 与终态 meta
→ 后台读取完整波形 → 人工确认接触起止 → 标记有效 / 作废
→ 重建 index.csv
```

流程约束：

- 录制中锁定受试者、场次、动作与采集布局，禁止修改身份配置。
- "结束采集"只关闭样本边界，不断开串口、不停止实时显示。
- 断连、写盘失败、队列溢出、缺块、基线不合格都会标为 `incomplete` 并保留文件。
- 作废是移动到回收区并重建索引，不是删除文件。

## 10. 写入位置与异常处理

### 10.1 从原始接收位置记录

数据流：串口解析得到原始块 → 在接收线程记录一次时间 → 交给录制器（先重排后写盘）→ 再进入显示预处理与界面刷新。

- 训练数据不得从界面刷新回调获取：界面只取最新快照，会合并中间帧。
- 录制使用独立写盘线程与有界队列（当前容量 4096 行），磁盘停顿不阻塞接收。
- 队列满或写盘失败时记录错误并标记该帧未保存，不静默丢弃。

### 10.2 完成状态与文件

- 开始时创建目录并写入 `recording_status=recording` 的 meta，保证异常退出后仍有记录可查。
- 停止时先关闭接收边界（以按键时刻为准），再排空队列、`flush` + `fsync`、关闭文件。
- 元数据一律"写临时文件 → `os.replace`"，不会出现半截 JSON。
- 异常中断后保留可用数据，尾行是否完整需人工检查；任何格式都不保证断电无损。
- 写盘线程只捕获 `OSError` / `ValueError`，其他异常会导致线程退出而队列继续积压，最终以"队列溢出"暴露。

## 11. 采集质量判定

样本的 `quality_status` 取"接收完整性"与"接触语义"中较严重的一方。

### 11.1 接收完整性（`receive_integrity_v1`）

逐块检查首帧空缺、中间间隔、尾帧空缺，阈值以录制前 5 秒实测间隔中位数为参考：

- 提醒阈值 = max(0.2 s, 5 × 参考间隔)
- 失败阈值 = max(1.0 s, 20 × 参考间隔)
- 参考不足或抖动过大时使用固定下限，并在最终结果中至少标 `warn`

各块结果写入 `meta.quality.integrity.blocks`，异常事件写入 `events`（最多 100 条）。

**注意**：该规则只使用主机接收时间，不解释 ADC 大小。它无法发现设备重复发送、帧内容停滞、位翻转或整行跳变。

### 11.2 接触语义（`contact_activation_v1`）

逐块按"连接基线 − 原始 ADC"的正向下降量统计：

| 参数 | 默认值 | 用途 |
|---|---|---|
| `threshold_counts` | 100 | 单点超过该值才算"该块被接触" |
| `onset_counts` | 20 | 起点阈值，能抓住缓爬坡动作的起步 |
| `edge_counts` | 50 | 终点与"仍在接触"判定，防止余振拖尾 |
| `edge_pad_s` | 0 | 端点外扩，用于对齐人工标注习惯 |
| `hug_min_regions` | 3 | 多区域动作至少同时接触的块数 |
| `max_block_switches` | 0 | 单区域动作允许的主块切换次数 |

输出的 `activation` 对象包含 `primary_block`、`region_ids`、`region_set`、`region_count`、`max_delta_counts`、`block_switches`、`contact_start_s`、`contact_end_s`、`contact_frames`、`open_at_end`、`frames_evaluated`。

## 12. index.csv

固定 9 列，可从各样本 meta 完整重建：

```csv
subject_id,session_id,trial_id,action_id,duration_s,accepted,sample_path,recording_status,quality_status
student01,session_20261117_01,pat001,0,4.209,true,student01/session_20261117_01/pat/pat001,complete,pass
```

- `accepted` 为 `true` / `false` / 空（对应 meta 中的 `null`）。
- `sample_path` 相对数据集根目录，使用 `/`。
- 清单在保存完成、质量标记更新、作废与恢复后重建；重建时逐个读取 meta，读取失败的样本不会进入清单，也不会报警。
- 原始样本与 meta 是依据，清单不是唯一数据来源。

## 13. 训练使用

### 13.1 读取口径（必须统一）

1. 读取 `index.csv` 或直接遍历 `*/*/*/*/meta.json`，按 `accepted` 与 `quality_status` 筛选。
2. 读取 `layout_id` 指向的布局副本，取得每个块的 `rows`/`cols`、`saved_to_raw_index`、`valid_mask`。
3. 按 `block_id` 分组读取 CSV，取每块前 `rows × cols` 列，按保存顺序 reshape。
4. 用 `valid_mask` 排除空位点。**空位点的 ADC 可能是 0，不能用数值判断有效性。**
5. 按 `time_s` 对齐各块；不要按行号对齐，各块首帧时刻不同。
6. 基线相减前转为浮点，避免无符号下溢。

### 13.2 去重与重采样（重要）

实测（2026-11-17，4 条轻拍样本）：主机接收约 72 Hz/块，但设备**每帧重复发送 4 次**，实际新数据率约 **20 Hz**：

| trial | 接收帧数 | 重复段长度 | 新数据率 |
|---|---|---|---|
| pat001 | 302 | 中位 3、最大 3 | 20.1 Hz |
| pat002 | 307 | 3 / 3 | 19.7 Hz |
| pat003 | 258 | 3 / 3 | 19.9 Hz |
| pat004 | 287 | 3 / 3 | 19.9 Hz |

因此训练前必须：

- 按帧内容去重（或每 4 帧取 1），否则滑窗样本重复 4 倍，训练/验证随机划分会严重泄漏。
- 按约 20 Hz 计算窗口长度：0.5 秒动作只有约 10 个独立样本。
- 同一录制切出的多个片段必须属于同一个数据划分。
- 若目标是泛化到新受试者，应按受试者留出测试集。

### 13.3 数据规模

以 10 块、最大块 50 点、10 秒录制估算，单条 `raw.csv` 约 1.4 MB；300 条约 420 MB，可接受。容量与时长、块数、点数成正比，扩张前按真实配置重算。

## 14. 正式批量采集前的验收

先用少量样本验证完整链路：

1. 同一块的 CSV 数值与软件接收到的原始 ADC 一致（可用 `mean` 波形回放对照）。
2. 不同尺寸块能按固定方向恢复矩阵，`saved_to_raw_index` 可完整还原硬件顺序。
3. 点位掩码与实际布置一致；无效位置不因读数变化而改变。
4. 各块时间戳单调、块编号正确、样本边界与按键时刻一致。
5. 结束采集后能重新读取并看到完整动作波形，人工标注可保存并留痕。
6. 作废样本移入回收区且编号不复用；恢复后仍为 `accepted=false`。
7. 断连、写盘失败、基线不合格都能明确标记，异常样本不会自动进入训练集合。
8. 能从 meta 重建清单，统计每人、每动作的有效样本数。

预采集（pilot）在此基础上追加三项判据：

| 项目 | 判据 |
|---|---|
| 结构完整率 | 100% |
| 事件内丢帧 | 0 次（正常停顿应在事件之外） |
| 类内一致性 | 峰值变异系数 ≤30% |
| 类间可分性 | 3 类原始特征（峰值、激活点数、事件时长）不重叠，留一交叉验证明显高于随机 |

## 15. 已知限制

以下为当前实现的事实约束，训练与结论表述时需一并说明：

1. **没有设备帧序号、设备采样时间与协议校验字段**。`time_s` 是主机接收时刻；同一 CSV 行不代表同一瞬间；设备端丢帧无法证明，位翻转只要落在 0～4095 内就无法发现。
2. **多块不同步**。各块独立轮询或流式到达，跨块相位差实测 p95 约 7 ms、最大约 18 ms（异常停顿可达约 118 ms）。
3. **有效更新率约 20 Hz**，远低于接收速率，见 13.2。
4. **块内重复帧**（同一矩阵连发 4 次）目前不被完整性检查识别，只能靠训练侧去重。
5. **单块覆盖**。2026-11-17 的 4 条轻拍样本中，只有 BLOCK 03 有真实响应（峰值 316–599 LSB），其余 9 块为静息噪声（4–15 LSB）。多区域动作（拥抱，要求 ≥3 块同时接触）在补齐皮肤前无法通过语义判定。
6. **空位点保留原值**（可能为 0），解析时必须使用掩码。
7. **会话元数据记录界面选择值**，实际生效的接收模式与数据格式未落盘；`operator_id` 与实验条件为空。
8. **每条样本保存一份标定快照副本**，同源基线会出现多个编号。
9. **录制无时长上限**，忘记停止会持续写入；也没有单实例锁，两个窗口同时写一个数据集时索引会互相覆盖（最终可自愈）。
10. **崩溃后样本停在 `recording`**，目前没有启动自检补写终态；写盘线程异常类型收窄，可能以"队列溢出"形式延迟暴露。
