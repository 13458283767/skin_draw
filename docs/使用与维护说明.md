# SkinDraw 电子皮肤热力图

本页为详细说明；快速入口见[项目首页](../README.md)。以下命令均在项目根目录运行。

## 本地分支与显示模式

本项目的 Git 根目录为当前 `skin_draw` 文件夹。`main` 启动时使用 `MainWindow(raw_adc=False)`，先校准再显示 ΔADC；`test` 使用 `MainWindow(raw_adc=True)`，直接显示原始 ADC，不校准、不滤除跳变。

关闭软件后在本目录执行 `git switch test` 或 `git switch main`，再双击 `start.pyw`。切换前保存未提交修改；切换不会自动重启正在运行的程序。虚拟环境、日志和分析产物不纳入 Git，仍保留在本机。以下基线校准与异常过滤说明适用于本 main 分支。

## 人体14块预设

左侧“皮肤块布局”新增“恢复人体预设（14块）”。按用户示意图暂将①～⑭绑定为BLOCK 1～14；正面人体右侧显示在画面左侧。1/2右肩/左肩在顶部，3/4上臂、5/6下臂、11/12手依次向下；7胸部、8腹部在中央，9/10大腿在下方；右侧独立背面区为13背部、14腰部，不重复绘制肩、臂或腿。15/16若收到数据，放在背面下方并标记“未分配”。

预设可以在连接前启用。未连接的14块部位用浅色虚线占位框表示，没有传感器数值，也不计入设备数量、校准、帧率和统计。连接后的矩阵尺寸以实际报文为准，占位尺寸只用于安排空间。各部位位置由预设槽位决定，不按当前连接数量重新排队；若真实尺寸与占位假设不同，布局会为实际尺寸调整间距。短暂断流的已识别块继续使用原有过期提示。

人体布局按当前旋转后的矩阵宽高紧凑计算，不再为每块预留旋转后最大正方形空间。胸腹、手臂各自上下衔接，手掌位于大腿两侧，两条大腿靠拢，背部和腰部紧邻正面区域；保留标题所需间距，适应窗口时传感器方块更大。旋转或尺寸改变后，自动人体布局可能同步移动邻近块以避免重叠；手动摆放仍优先保留，点击恢复预设才重新排布。

仍可拖动单块，恢复人体预设只清除手动位置，保留旋转、镜像、选点和基线。预设不会自动旋转收到的矩阵；例如10×5的胸部数据可自行旋转成5×10，之后恢复位置仍保留方向。点击“恢复自动排列”返回原有紧凑网格，也保留方向。模式在本次运行的断开、重连中保留，重启默认自动排列；暂不保存手动位置到磁盘。

部位名称、编号和占位尺寸集中在 `src/skin_draw/presets/body_layout.json`，人体部位的紧凑排列计算在独立的 `body_layout.py`，不影响ADC处理或保存方向。配置中的旧row/column字段仅保留作示意，当前紧凑排列由人体部位关系决定。只有切换模式、连接块尺寸变化、旋转或窗口变化时调整布局；正常帧只更新原有块的颜色。空位可通过下述有效点位编辑隐藏；暂不绘制毫米尺寸的物理外轮廓。

可执行 `.venv\Scripts\python.exe tools\render_body_preview.py` 查看不连接串口的模拟预览，输出位于 `artifacts/body-layout-preview/`。预览为展示人体布局，将胸腹背腰四块旋转90度，该旋转仅由预览脚本设置，不是恢复按钮的隐含操作。

工作流程：**连接几块，就校准几块 → 保持无按压，各块各行独立采集约1秒且至少30个有效样本 → 每个传感器计算平均基线 → 实时显示按压引起的 ADC 变化。**

每个传感器对应一个独立正方形，颜色随响应值连续变化，不在传感器之间插值。支持 1–16 块、每块 1–16 行列，自动排列实际收到的数据；已验证 14 块、每块 16×16 时在 1000×720 窗口内完整显示。

## 有效点位与不规则皮肤（第一版）

硬件仍发送完整矩形，不要求空位发送0。先接收数据识别块尺寸，在左侧“皮肤块方向”选择BLOCK，点击“编辑有效点位”。编辑器按当前旋转、镜像后的方向显示完整矩阵：蓝色“有”表示有效传感器，灰色×表示空位，单击切换；悬停显示原始行列。点击“保存点位”生效，“取消”放弃修改，“全部恢复有效”后保存可恢复全部格子。

保存后空位透明，不着色、不显示数值、不接受选点；有效点数量、最小/最大/平均值和自动色阶均排除空位。旋转、镜像、拖动、人体预设和窗口缩放保留同一原始点的有效状态，不按ADC大小自动判断。允许全部隐藏，统计无有效数据时显示“—”；该块标题保留，仍可通过左侧下拉框重新编辑。

校准仅累计有效点的原始ADC，空位的基线和响应在处理矩阵中为0，仅用于保持矩阵尺寸，不代表该处有传感器。隐藏点不会触发异常行过滤或阻挡有效点校准。有效点突变超过800仍保留该行其他有效点的上一有效值；隐藏位置在原始及过滤后的ADC矩阵中保留此次收到的数值，不计入过滤点次。收到的完整原始矩阵始终不变。

连接中实际改变某块点位，会清除该块基线、过滤参考及旧响应，各行重新采集约1秒且至少30个有效样本，请松开该块。其他块继续显示；未改变有效点位直接保存不会重置校准。离线改变点位后，该块ΔADC等待下次连接校准。

配置保存在项目 `configs/sensor_masks.json`，第一次保存时自动创建，重启后自动加载。格式为 `version: 1`、`coordinates: "raw_row_col"`，`blocks`以BLOCK编号为键，各块 `valid` 为与原始矩阵同尺寸的布尔二维数组（true有效、false空位）。例如原始2×3矩阵：

```json
{"version": 1, "coordinates": "raw_row_col", "blocks": {"7": {"valid": [[false, true, false], [true, true, true]]}}}
```

配置尺寸必须与收到的原始行列完全一致；同编号尺寸改变时不套用旧配置，暂按全部有效显示，左侧提示重新编辑，并写入日志。若更换连接顺序，同编号但同尺寸的不同皮肤无法自动区分，需要重新核对点位。换电脑时随项目复制该配置。配置读取损坏会显示提示并保留原文件，修复后重启再编辑；写入失败会提示且不改变当前运行状态。

维护入口：`sensor_masks.py`负责配置与不可变掩码，`ui/sensor_mask_dialog.py`负责编辑，`live.py`在锁内切换处理状态。掩码不增加串口数据，也不增加逐帧写盘；只在保存时写配置，正常刷新继续复用绘图项。当前仍未实现训练文件录制；后续录制应保留完整原始矩阵并随数据保存采集时的点位配置。

## 拖动皮肤块

按住某一块的 **BLOCK 标题或彩色区域**，用鼠标左键拖到想放的位置；只移动这一块，其他块保持不动。悬停可拖区域时鼠标变为手形，选中块显示青色虚线边框；标题和行列标号一起移动。单击仍可选点，拖动画布空白处平移画面，滚轮缩放。允许自由摆放、相互覆盖，重叠时点击和拖动作用于上层皮肤块。

拖动后的布局在实时刷新、重新校准、旋转镜像和窗口缩放时保留，本次运行中断开重连也会按 BLOCK ID 记住位置。“适应窗口”显示整个布局；左侧“恢复自动排列”重新自动排布所有块，保留旋转和镜像。关闭软件后恢复默认布局。

## 旋转与镜像

在左侧“皮肤块方向”中选择 BLOCK，或直接点击热力图中的传感器，然后点击“左转 90°”“右转 90°”“左右镜像”或“上下镜像”。每次操作均相对当前画面方向执行，仅改变所选皮肤块；“恢复原始方向”清除该块的旋转和镜像。

旋转后自动按显示长宽重新排列，14 块仍可适应窗口。选点读数始终对应原始传感器行列，原始 ADC、基线校准和异常行过滤不受影响。方向按 BLOCK ID 在本次运行期间保留，断开重连或重新校准后仍有效；关闭软件后恢复默认。

## 启动

在项目目录双击 start.pyw。如果系统未关联 .pyw，在当前目录打开 PowerShell：

```powershell
./.venv/Scripts/python.exe -m skin_draw
```

本目录已安装依赖。复制到另一台 Windows 电脑后，需要 Python 3.11 或更高版本，再执行：

```powershell
powershell -ExecutionPolicy Bypass -File ./install.ps1
```

该命令只为当前脚本进程设置执行策略，不修改系统策略。安装脚本使用项目内 .venv；依赖版本锁定在 requirements-lock.txt。双击启动失败时会弹出说明并写入 startup-error.log。

## 运行日志与传输中断排查

正常启动程序后自动记录日志，点击窗口右上角“打开日志目录”即可查看。优先保存在程序目录 `logs/`，目录不可写时使用 `%LOCALAPPDATA%/SkinDraw/logs/`。日志为 UTF-8 文本，可用记事本打开；文件名包括启动时间和进程号，记录包含毫秒时间、时区、严重级别和模块。每次串口连接另有 `session` 编号，便于区分断开重连。

记录内容包括：程序及依赖版本、串口与设备描述、发送方式、明文/二进制选择、二进制协议版本和帧尾规则、打开/关闭、首批字节、各块首帧和尺寸变化、稳定基线校准完成（记录各行样本数、累计有效时长）、重新校准、异常行过滤、轮询超时和恢复、解析异常、数据中断与恢复、用户主动断开、异常堆栈和界面刷新延迟。

| 日志信息 | 如何判断 |
|---|---|
| 串口采集异常 + Traceback | 查看具体的打开、读、写错误；可能是端口占用、驱动、USB断开等，日志保留系统原始错误 |
| 串口连续无字节 | 至少3秒没有读到字节；`received_any` 区分从未收过数据和接收后停止，不直接断言硬件断线 |
| 串口有字节但无有效传感器帧 | 字节仍在到达，但至少3秒没有解析出传感器矩阵；检查格式、未就绪状态和解析错误 |
| 皮肤块有效数据超时 | 连续模式下某个已收到过的BLOCK停止更新；阈值为3秒与该块估计间隔3倍中的较大值 |
| 轮询应答超时 | 包含目标ID、是否已识别的设备、本次等待收到的字节数及解析错误增量；检测未连接ID时超时属于正常探测结果 |
| 串口解析异常 | 区分明文列数/数字错误、ADC越界、二进制字段错误、0x0A帧尾错误和残帧超时，附最近最多96字节的HEX片段 |
| ADC异常行已过滤 | 有效矩阵已到达，但触发突变过滤；包含部分异常原始行、保留的有效行和累计过滤点数 |
| 界面刷新统计中的耗时 | `update_ms_p95` / `update_ms_max` 为快照读取到界面提交的处理耗时；`latest_sample_age_ms_p95` 为最新块从后台收到到界面提交的时间，包含界面调度等待，不包含硬件采样、传输和屏幕实际呈现 |
| 串口字节接收恢复 / 有效数据帧恢复 / 皮肤块数据恢复 | 对应中断后的恢复事件，附中断时长 |

正常接收每5秒汇总一次字节速率、各BLOCK接收数量/频率、最近帧间隔、格式计数、错误计数及残留缓冲大小。界面每5秒记录刷新快照数量、帧序号、校准计数和累计过滤点数。高频重复异常会合并或限频，不逐帧写完整矩阵；最后一次串口汇总仍保留累计错误数。v0.5没有CRC；帧尾校验通过不代表负载没有误码。

日志由独立线程写盘，队列上限1000条；拥堵时丢弃日志并在后续记录中提示，不阻塞串口等待磁盘。单文件约5 MiB轮换，每次运行最多保留当前文件及4份备份，启动时清理至最近10次运行（正在被其他实例占用的旧文件可能暂留）。日志不是完整原始数据录像，也无法仅凭无字节现象证明断线的具体硬件原因。

出现中断后，记下大致发生时间，将**当次运行的 `.log` 文件和同名前缀的 `.log.1`～`.log.4` 备份一起保留**，即可对照接收、解析、过滤和显示记录。旧版本运行期间的故障无法追溯补记；需要重新启动更新后的程序。

## 连接、校准和按压显示

1. 连接电子皮肤、RS485 总线和 USB-RS485 转换器，给硬件供电。转换器安装好驱动后，Windows 中应出现 COM 串口。
2. 打开软件，点击“刷新”，选择硬件对应的 COM 端口。
3. 在波特率下拉框选择115200（1倍）、230400（2倍）、460800（4倍）、921600（8倍）或1843200（16倍），默认115200，必须与硬件固件一致。保持“自动识别发送方式”和“自动识别：明文 / 二进制”，**先松开所有传感器，再点击“连接并校准”。** 软件以所选波特率、8N1打开串口，先监听最多2.3秒；收到有效数据或二进制未就绪帧时进入连续接收，否则逐个查询ID 1–16。连接期间锁定波特率选择，断开后可切换重连；日志记录实际选择值。此下拉框手动选择接收速率，不自动探测波特率，也不向硬件发送改速命令。
4. 连续模式收到哪块就处理哪块；轮询模式检测后只查询已响应的 ID（含二进制未就绪设备），不要求固定连接 14 块。每个皮肤块收到完整矩阵后，各行独立检查并累计稳定的原始样本；异常行不影响其他行。
5. 保持无按压，等待各块完成校准。每行需同时达到约1秒稳定数据和至少30个有效样本。进度条显示最慢有效行的百分比，旁边列出待完成的原始行、最少样本数和累计有效时长；悬停可查看逐行详情。已完成行冻结基线，整块所有有效行就绪后开始显示该块响应，其他已完成块继续实时显示。
6. 显示“基线已就绪，可以按压传感器”后开始按压。方块随新扫描数据更新颜色。基线保持固定，不会随着持续按压自动漂移。
7. 需要重设零点时，松开所有传感器，点击“重新校准基线”，各行重新建立多帧参考并累计稳定样本。
8. 点击“断开硬件”停止采集并释放串口，画面标记为非实时。下次连接重新检测设备和校准。

首次检测只使用实际响应的 ID。新增或更换皮肤块后请断开再连接，重新检测。运行中某块超时，仍保留该块的位置，不清空或重排整张图。它的校准计数暂停，其他块继续；某块形状变化时只重新校准该块，不清除其他块的基线。

数据稳定时，90帧/秒约使用91个样本，45帧/秒约使用46个样本，校准约1秒完成；20帧/秒受至少30样本要求限制，需要约1.45秒。异常或不稳定会延长等待。当前单块响应超时为0.8秒。

## 稳定校准的判定与限制

校准只使用有效点位，按原始矩阵行独立进行。先观察最近7份该行数据，逐点计算中位数；至少5份数据的所有有效点都在中位数±100 ADC以内，才建立参考。后续整行有效点均在固定参考±100以内时累计原始值；某行连续7份不符合参考，会清除该行未完成的累计并重新建立多帧参考，避免首次异常锁死。已经完成的行和其他块不受影响。

这里的100是无按压校准稳定带，不改变绘图阶段的800突变阈值，也不是固定ADC上下限。校准结束后基线冻结，重复异常值不会因持续出现而自动放宽运行时过滤。请保持无按压；软件无法仅凭稳定性判断“持续错误但稳定的数据”或“持续按压”是否正常。

时长按接收时间累计：仅接受当前有效样本的采样间隔，单次最多计0.1秒，超过0.25秒的间隔不计；不把断流、等待或重复旧值充当稳定时长。至少30个真实有效样本条件仍保留。每行只缓存最近7份候选数据以及计数和累加值，不积压全部历史帧；明文和二进制使用同一套校准逻辑。

无有效点的空行无需校准。整块全部隐藏时自动跳过校准；重新启用点位会重新校准该块。每5秒的界面日志包含校准百分比、待完成行及样本/时长详情，完成事件包含实际逐行样本数和时长。

## 受压方向与数值含义

### 异常值过滤

当前采用 **有效点突变就丢弃该行的有效点**：一行中任意有效点满足 `abs(当前原始 ADC - 上一有效行对应点 ADC) > 800` 时，本次该行有效点不用于显示更新，保留上一有效值。隐藏空位不参与判断。其他行、其他块里的正常数据照常更新；等于 800 保留，增大、减小均检查。

例如上一有效行是 `2500,2500,2500`，当前行 `1003,2100,2400`，该行整行丢弃，显示仍为 `2500,2500,2500`。下一帧该行变为 `2400,2100,2400`，全部点变化不超过 800，就在这一帧立即采用新行，无等待、无时间平滑。被丢弃的整行不更新比较参考，所以重复异常报文也不会自动放行。原始报文仍保存原值，不删除矩阵行或改变传感器位置。

不使用固定 ADC 下限或基线差值上限；判据是某个点是否突变，不要求整行所有值同时降低。首次收到某块、重校准或形状变化时，先执行下述稳定校准；整块校准完成后用基线初始化运行时过滤参考，不直接信任第一帧。重新连接也清除运行时过滤计数。真实变化若一次超过 800，也按同一规则过滤；若实际工作范围改变，可重新校准建立新参考。

原始 ADC 保留，选中或悬停被替代行里的点会提示“显示保持上一有效值”。状态区统计被替代的有效点次，一条有三个有效点的行丢弃一次计三点次，隐藏空位不计数。校准与运行时过滤分开：各行仅用通过稳定性检查的原始样本平均，不使用被保持的旧值；其他正常行不因某行异常而被丢弃。校准期的拒绝不计入运行时过滤点次，等待原因见校准详情。持续整块无有效数据时仍按原有机制标记过期。

默认你的传感器受压后 ADC 变小：

```text
baseline[id][row, col] = 该行满足时长和样本数要求的有效原始 ADC 平均值
受压变小：response = max(0, baseline - raw_adc)
受压变大：response = max(0, raw_adc - baseline)
```

点击 **“受压变小 ↓ · 点击切换”** 可切换为“受压变大 ↑”；再次点击切回。切换只改变计算方向，不重新采集基线，不修改原始 ADC。

- 热力图与统计显示 **ΔADC**，不是已标定的压力或温度。反方向变化按 0 着色。
- 点击方块锁定点位，下方同时显示原始 ADC、基线和有符号的“当前 ADC − 基线”；界面行列从 1 开始。
- 硬件连接时默认固定色阶 0–1000 ΔADC，可调整上下限。颜色饱和不会截断原始数据或统计值。
- 自动色阶可选，比较前后按压力度时建议使用固定色阶。
- 低值使用配色最低色。灰色表示校准期间尚无显示值，或固定物理布局模式下的数据缺失。
- 基线相减使用浮点数，避免 uint16 下溢；原始 ADC 保留为整数。

## 布局与交互

本次连接识别几块就绘制几块，每块按数据中的行列数生成矩阵，不需要手工设置尺寸。按 BLOCK ID 排序，编号可以不连续。真实采集期间布局与单轮收包结果分离：临时漏帧不会删除块、重置缩放或清空画面；窗口缩放只移动原有图元，尺寸未变的重复通知不会触发布局重建。

短暂漏帧时，保留最多两轮的上一幅图案，并以橙色虚线和橙色标题明确标记“暂未更新”。这些旧值不参与当前统计、基线或实时读数；连续三轮缺数据后该块变灰，位置仍保留。恢复数据后在原位置更新。不要把橙框内保留的图案当作最新测量结果。

滚轮缩放、拖动画面，按 F 或“适应窗口”恢复总览。方块保持正方形。悬停查看读数，单击锁定点位，单击空白取消。密集阵列隐藏外围行列数字；启用格内数值后，在方块足够大时显示，放大即可查看。

“导出 PNG”保存当前绘图区与色条，是截图功能，不是数据录制。

默认启动不会生成模拟图。左侧底部的“使用模拟数据测试”可单独开启绘图测试，模拟模式显示原始 ADC，明确标记“模拟预览”。演示下空格暂停/继续，“单步”暂停并前进一帧。硬件连接期间不能切入模拟模式，防止模拟值覆盖真实数据。

## 协议和连接条件

### 接收速率显示

热力图上方显示“接收 N 块帧/秒”，表示最近 1 秒 `(当前时刻−1秒, 当前时刻]` 内实际收到并交付采集处理的有效单块矩阵总数，每秒刷新一次。点击旁边的“各块 … 帧/秒”可查看每个 BLOCK 的实收帧数，停止来数据的已识别块仍列出并显示 0。例如 14 块各收到 30 帧，总计为 420 块帧/秒，不代表全身每秒更新 420 次，也不是屏幕帧率。

统计在后台接收处、异常行过滤前进行：校准期间的数据和后续被行过滤的有效矩阵都计入；解析失败、未就绪回复、轮询时非目标 ID 回复和模拟数据不计入。界面跳过中间帧不影响计数。计数只保存最近一秒的接收时间，静默后在下一次统计刷新时归零；主动断开或采集失败立即清零，重新连接使用新计数器。开始采集不足一秒时显示已经收到的数量，不按比例推算速率。

### 数据协议

支持明文和 neo_SKIN_01 v0.5 二进制数据，默认逐帧自动识别，可在同一字节流中交替出现；也可以在连接前选择“仅明文 BLOCK”或“仅二进制 v0.5”。“数据格式”和“连续接收 / 指令轮询”是两个独立选项，两个发送方式都支持这两种格式。二进制已切换到 v0.5，不再提供旧版 CRC 帧的解析或校验选项；设备与转发主机也需使用 v0.5 帧长，自动识别不用于区分二进制版本。

- 明文：`BLOCK_<ID>,<rows>,<cols>:` 头部、rows 行逗号分隔的 ADC 数据，以及可选 `END` 行。
- 二进制：`AA ID M N [2×M×N 字节 ADC] 0A`，总长 `5 + 2MN`。ID、M、N 范围为 1–16，ADC 为 0–4095，大端 uint16，按行优先排列。接收的是原始二进制字节，不是“AA 01 …”形式的十六进制字符串。
- `M=N=0` 是 5 字节未就绪帧（例如 `AA 01 00 00 0A`），校验帧尾后不生成矩阵、不参与校准；轮询模式保留该 ID，后续继续查询。仅一个维度为零视为非法帧，预留状态扩展尚不支持。
- 收满声明长度后，始终检查最后一个字节为 `0x0A`；帧尾错误的数据不参与绘图和校准，并记录具体错误。没有 CRC 开关。文档 3×3 示例为 `AA 01 03 03 08 00 04 00 02 00 0B B8 09 C4 07 D0 03 E8 05 DC 09 C3 0A`，共 23 字节。
- 支持半包、粘包、负载中的 AA/换行字节；不按换行拆分二进制帧。非法字段、越界 ADC、帧尾错误会触发重同步，拒绝当前候选帧后从后续候选头重新检查。二进制残帧默认 250 ms 超时，覆盖 115200 下最大 517 字节帧约 45 ms 的传输时间，不使用会截断长帧的固定 5 ms 超时。无 CRC 时不能保证发现所有丢字节、位错或失步后的伪帧，原有异常行过滤仍在解析后执行。

收齐声明的全部数据行即完成该块；支持半行、粘包和跨块切分。检查 ID、行列数、字段数量与 0–4095 范围；坏行使当前块失效，遇到新合法头部恢复同步，不把后续行错位拼接。

轮询命令保持 `hello num <ID>\r\n`，同一总线上只保持一个未完成请求。明文响应后消费可选 END；二进制按声明长度收齐即结束，短暂等待收发切换。超时后等待总线安静，减少迟到数据污染。连续模式不发送采集命令。串口波特率按下拉框选择，默认115200，其他参数为8数据位、无校验、1停止位、无流控，期望使用自动控制收发方向的USB-RS485转换器。

需要主机特殊 RTS 控制的转换器仍需对应适配。两种帧均没有请求序号或设备时间戳，不能绝对区分特别迟到的同 ID 回复，也不能只凭接收顺序保证还原板子轮询的硬件轮次；明文也没有校验和。固件发送 16×16 二进制矩阵时需要容纳 517 字节的发送缓冲区。v0.5 解析流程与实施边界见 [二进制v0.5解析说明](二进制v0.5解析说明.md)。

没有串口时检查 USB 接线和驱动；打开失败时关闭占用串口的串口助手；没有 BLOCK 时检查供电、RS485 A/B、共同参考地及固件指令。

采集和校准逻辑不依赖界面。后台线程独占串口，明文和二进制都转换为同一个 Block 数据模型，逐份执行过滤与校准，并为本次收到的块缓存不可写的按压响应数组。新数据到达后通知主线程；距离上次提交已满 4 ms 时直接安排更新，否则等待剩余时间。通知会合并，界面只取各块最新状态，不排队回放中间帧；后台仍逐帧过滤和校准。4 ms 是连续提交的最小间隔，不是硬件采样率或屏幕实际帧率保证，主线程繁忙时仍可能延后；数据到达慢于该间隔时（例如每块约 25 ms 的常规采集）节流不参与，每次到达都立即提交。

该节流预算按毫秒计算，因此界面路径统一使用高分辨率时钟 `perf_counter`。Windows 上 `time.monotonic()` 实际是 `GetTickCount64`，粒度约 15.6 ms：用它相减会让"已过时间"只能取 0 或约 15.6 ms，把提交间隔在不知不觉中量化成 15.6 ms 的整数倍。启动时另调用 `timeBeginPeriod(1)`，让 Qt 的 `PreciseTimer` 不受系统默认定时器粒度限制。

只有响应更新的块才重新转换矩阵方向、复制显示数组和映射颜色；无自定义行列映射时，旋转/镜像使用数组视图，减少中间复制。快照共享已经定型的只读基线数组，仅复制控制字典和校准中的累计数组，保持线程之间的状态隔离。原始 ADC 与过滤结果分别保留。切换方向、重校准、形状变化以及缺帧恢复会正确更新缓存。

连接速率、累计数量及最小/最大/平均值等信息每 200 ms 更新一次，使用最新快照，不排队显示旧统计。校准进度、设备集合、缺帧状态变化立即刷新；选中或悬停的传感器有新数据时立即刷新读数。颜色仍按热力图自己的更新节奏变化。没有数据时每 500 ms 检查过期状态，无需高频空转；断开和关闭使用取消事件，不强制终止线程，旧画面标记为非实时。

HeatmapView.set_frame(raw_frame, display_values=None, layout_blocks=None) 可独立复用。只传原始帧显示 ADC，传入 dict[block_id, float_array] 显示派生响应，原始帧不变。空显示字典表示校准中等尚无可绘制响应的状态。实时采集另传 layout_blocks，使用本次连接实际见过的块定义稳定几何布局；它只提供形状，不冒充当前帧的测量。省略此参数仍可用于按输入帧自动增减的普通绘图。可选 set_layout() 供开发者指定物理位置。

内部实时路径可传关键字参数 `changed_ids`，指明所有显示值变化的块（包含增加/移除的响应），复用其他块的已验证显示数组。外部调用者使用可变数组时应省略此参数，保留完整校验与复制。布局重建会自动全量刷新；色标、间隙与旋转/镜像操作独立使对应显示更新，不依赖下一帧到达。

使用 `.venv\Scripts\python.exe tools\benchmark_display.py --output artifacts\display-benchmark.json` 可进行不连接硬件的可重复离屏测量：14 块、每块 65 个位置、每次只收到一个块，预热 50 次后统计 1000 次。该测量包含样本处理、快照、界面提交与事件处理，不包含硬件采样、串口传输、界面调度等待或屏幕实际呈现时间；运行时负载会影响结果。历史基准报告已归档到 `artifacts/cleanup-backup-20260926.zip`，旧结果不代表当前版本性能。实机应结合界面耗时日志、各块接收频率和过滤记录判断。提高硬件侧每块采样/发送频率仍需独立优化板端轮询与总线带宽。

使用 `.venv\Scripts\python.exe tools\benchmark_latency.py --interval-ms 4` 可离屏测量"数据到达 → 显示值已提交到热力图"的等待时间：16×16 单块、约每 1 ms 到达一次（远快于真实硬件，用于让节流确实生效），预热后统计 400 次，输出中位数、均值、P95 和最大值。可用 `--interval-ms` 对比不同节流值。该测量同样不包含硬件采样、串口传输和屏幕实际呈现；它刻意让到达快于节流，因此反映的是连续快速更新时最坏一侧的等待，而不是慢速采集下的延迟。同一路径的实机端到端数据来自日志中的 `latest_sample_age_ms_p95`，该字段现在也基于高分辨率时钟，可以分辨毫秒级变化。
