## 1. 评审结论与排序原则

当前已经具备原始 ADC 录制、固定方向重排、版本化布局、动作类别、受试者/场次管理、后台写盘和人工有效标记等基础能力。下一步应先补齐“接收是否完整、文件是否真正收尾、样本是否允许进入训练”的判断，再增加批量操作效率功能。

优先级定义：

| 优先级 | 判断依据 | 建议执行时点 |
| --- | --- | --- |
| 高 | 已确认会造成严重缺失样本被误认为完成、训练标签含义混淆，或故障收尾状态不可靠 | 大批量正式采集前完成 |
| 中 | 影响复核效率、实验可重复性和长期使用，通常不会直接改写当前原始 ADC | 高优先级完成后、小规模试采期间完善 |
| 低 | 操作便利性、进一步测量能力或需要硬件配合的扩展 | 核心流程稳定后按实测需要实施 |

高优先级内部的编号也是建议实施顺序。阈值和性能指标未经过实机验证时，不能写成已经验证的固定标准。

## 2. 已实现且应保留的设计

以下能力已经存在，不能重复当成“尚未实现的优化”：

1. 原始块在 `LiveBuffer.receive()` 内、显示预处理之前交给录制器；记录不依赖 GUI 刷新是否合并中间帧。
2. CSV 保存完整 ADC；只按固定布局调整位置，未滤波、未扣基线，隐藏空位的读数也保留。
3. 录制时冻结方向和通道映射；布局与掩码版本化，旧版本不直接覆盖，重启能够恢复。
4. 每块使用主机接收相对时间；CSV 一行是一块新收到的矩阵，不是全身同步帧。
5. 后台写盘使用有界队列；已有溢出、写盘错误、尺寸不符及整段缺块记录。
6. JSON 使用临时文件替换，正常结束时写盘线程执行刷新与关闭。
7. 受试者和场次已有下拉选择、新增、删除、回收与恢复；删除不重排其他编号，回收内容不进入训练索引。
8. 录制期间锁定身份、动作和布局编辑；结束后可人工标记有效或作废。
9. M3 滤波在主界面默认关闭，可以手动切换，显示处理不改变原始 CSV。
10. 当前动作预设为轻拍 `pat`、握持 `grasp`、拥抱 `hug`，使用 `actions_v2`；旧表已有归档。

基线策略沿用已讨论的方向：**采集保留原始 ADC 和可辨识的无接触参考，训练前再决定如何计算、扣除基线及归一化。** 显示基线尚未就绪，不应单独成为禁止原始 ADC 采集的理由。

## 4. 高优先级：正式批量采集前完成

### H01. 完整性检查与异常结束判定

**当前问题与依据**

- `RawSampleRecorder.stop()` 的完成判定关注写盘、队列、已记录错误和整段未出现的块，未将异常结束原因直接纳入正常/异常判断。
- 某块只要收到过一帧，就不会被列入当前 `missing_block_ids`。
- 虽然记录了首帧、末帧和最大间隔，但尚未对开头等待、中间空缺、结尾停更统一判级。
- 本次复现：录制 10 秒、只收到一帧，分别以 `user_stop` 和 `disconnect` 结束，两者都得到 `status=complete`。

**建议逻辑**

1. 开始前为每个预期块获取正常接收间隔参考，使用近期正常、有效的间隔估计，保存估计方法与样本数。
2. 在录制开始时固定该参考和质量规则，不随着本段断流自动放宽。
3. 逐块记录首帧时间、末帧时间、帧数、最大相邻间隔及异常区间；限制异常明细条数，同时保留总次数，避免记录无界增长。
4. 使用独立定时检查发现持续静默；没有下一帧到来时也必须更新异常提示。
5. 停止后计算首帧等待、中间间隔、末帧到结束的空缺，分别判定。
6. 单块断流时保留其他块的记录；串口断开、写盘失败等明确故障应结束该段并保留文件。
7. 分离录制状态与质量状态，人工审核作为第三个维度。

| 字段 | 建议语义 |
| --- | --- |
| `recording_status` | `recording` / `finalizing` / `complete` / `incomplete`；说明录制与文件收尾状态 |
| `quality_status` | `pass` / `warn` / `fail`；说明完整性检查结果 |
| `accepted` | `null` / `true` / `false`；说明人工审核结果 |

正常停止且文件写完，但存在严重时间空缺，可以是 `complete + fail`。异常断连或收尾失败应为 `incomplete + fail`。正常点击关闭软件时，即使已尽力排空写盘，也应明确为录制被中断；不能仅因文件可读就认定动作完整。

候选阈值可以沿用讨论方案：`W=max(0.2 秒, 5×T)`，`F=max(1 秒, 20×T)`。它们仅是试采起点，不是最终标准。串口缓冲可能使主机接收出现成批到达，需检查间隔分布，不能把大量接近零的间隔直接当成硬件采样周期。低速模式参考不足时应提示等待或使用明确配置的阈值。

**验收条件**

- 10 秒只收到一帧，不能通过完整性检查。
- 每块开头迟到、中途静默、提前停更都能给出块编号、时间范围和原因。
- 断连即使已写入多帧，也不能获得正常结束的质量结果。
- 没有硬件帧序号时只报告接收空缺，不宣称准确丢帧数量。
- 0、4095、梯形无效格及其他合法 ADC 不因数值外观触发接收完整性失败。

**代码入口**：`dataset.py::RawSampleRecorder.snapshot/stop/_write_meta`，`main_window.py::_refresh_recording/_show_sample_result`，`live.py::receive/finish_scan`。

### H02. 明确参与块并加强开始前检查

**当前问题与依据**

`start_recording()` 直接把整个固定布局的块集合当作 `expected_block_ids`。布局保存又会保留过去配置过的块，因此“完整人体布局”和“本场次实际参与范围”容易混在一起。`_check_recording_shapes()` 只要求至少一块与布局相交，未要求每个必需块都存在或仍在更新。本次构造预期 `[1,2]`、仅收到 `[1]`，开始前检查可以通过。

**建议逻辑**

- 首次创建场次时明确选择参与块，列表来源为固定布局；显示已连接、离线、尺寸不符状态。
- 一旦该场次产生样本，固定参与集合；集合变化应创建新场次，保留当前“场次条件固定”的原则。
- 开始前逐块检查存在、尺寸匹配、新鲜度以及接收参考是否足够，不能只检查交集。
- 全部检查通过后生成不可变录制计划，并在打开数据接纳边界附近再次核对状态，缩小检查与真正开始之间的时间差。
- 布局外的数据应明确提示并按约定记录异常；不能在录制中临时加入新块、改变列数或掩码。
- 基线是否已经显示就绪，与原始数据是否可录制分别判断。

**验收条件**

- 预期两块只在线一块、某块只留有旧缓存、尺寸不符时不能正常开始。
- 只接部分皮肤时，明确选择的本场次范围可以正常采集；未参与块不算缺失。
- 重启后恢复场次的参与集合；已有场次禁止静默变更。

**代码入口**：`main_window.py::_check_recording_shapes/start_recording`，`DatasetStore.open_session`，`RecordingPlan.expected_block_ids`。

### H03. 写盘收尾状态与线程生命周期

**当前问题与依据**

- `finish_recording()` 在 GUI 线程同步调用 `recorder.stop()`，后者等待写盘结束；队列拥塞等待和线程等待在代码中分别可达 5 秒、15 秒，故障时界面可能长时间不响应。
- `_SampleWriter.finish()` 在线程仍存活的情况下记录错误，随后仍将 `_thread` 设为 `None`。
- 本次用“始终报告存活”的线程替身注入超时，确认错误产生后线程引用被清除。该复现证明状态管理问题，不代表已实测磁盘阻塞持续时间。
- 若旧写盘流程尚未停止，不能把“已经停止接纳新数据”当成“样本文件已关闭”。

**建议逻辑**

```text
IDLE → PREPARING → RECORDING → FINALIZING → IDLE
                                      ↘ ERROR/RECOVERY_REQUIRED
```

- 点击结束时，在录制锁内关闭接纳边界并记录结束时间；排空、文件刷新和索引操作交由受控后台收尾任务。
- `FINALIZING` 状态显示“正在保存”，保持 GUI 响应，并继续禁止新录制、身份删除/恢复和配置修改。
- 收尾超时保留线程引用、文件归属和错误状态；禁止旧线程仍可能写入时重开下一条。
- 修复队列满导致停止标记无法入队的退出路径；退出机制不能完全依赖向满队列塞入一个哨兵。
- 只有线程确实退出、文件关闭、元数据提交成功后，才报告最终结果。
- 写盘故障一经确认，应立即提示并停止本段录制，避免继续显示采集中却持续丢弃行。

**验收条件**

- 模拟磁盘变慢、队列满、写盘异常、收尾超时，GUI 仍可显示状态。
- 旧线程仍存活时不能再次开始，也不能回收其受试者或场次目录。
- 超时不清除唯一线程引用，不产生文件尚在写入的成功提示。
- 正常收尾仍保持已接纳行数、实际写入行数和元数据一致。

**代码入口**：`_SampleWriter._run/finish`，`RawSampleRecorder.active/start/stop`，`main_window.py::finish_recording/closeEvent`。

### H04. 训练索引与有效审核规则一致

**当前问题与依据**

- `index.csv` 只有受试者、场次、次数、动作编号、时长、有效标记和路径，没有 `labels_id`、`layout_id`、录制状态和质量状态。
- 当前 `actions_v1` 与 `actions_v2` 的同一数字编号可以表示不同动作；虽然样本元数据已有版本，仅依赖清单编号仍有混用风险。
- UI 通常只给完成样本开放“标记有效”，但 `DatasetStore.update_accepted()` 仅阻止仍为 `recording` 的样本，没有统一拒绝 `incomplete`。本次直接调用底层接口，确认不完整样本可被设为 `accepted=true`。

**建议逻辑**

- 在元数据与索引中统一保存类别、布局及质量规则版本。
- 索引至少增加 `labels_id`、`action_name`、`layout_id`、`recording_status`、`quality_status`、主要异常原因。
- 正式训练导出统一检查：文件正常完成、完整性未失败、人工有效标记为真、配置引用可解析。
- `warn` 样本可以人工复核，记录放行说明；`fail` 或 `incomplete` 禁止直接标为有效。修复后须重新验证，不能仅改一个布尔值。
- 约束放到底层数据接口，GUI、脚本和后续批量审核共用规则。
- 类别表和布局使用不可变版本快照；可增加内容摘要，防止同一版本号对应不同内容。
- 旧样本缺少新字段时标为 `unknown`/待验证，通过明确迁移流程处理，不能默认为 `pass`。

**验收条件**

- 两个类别版本的相同编号不会被直接合并成同一种动作。
- 直接调用数据接口，也无法把未完成或质量失败样本设为正式有效。
- 索引重建不改变既有样本的动作含义、人工结论和原始数据。
- 导出只读解析元数据和配置，不依赖当前 UI 正在选择哪个布局或动作表。

**代码入口**：`DatasetStore.INDEX_HEADER/update_accepted/rebuild_index/ensure_labels/ensure_layout/open_session`，`main_window.py::mark_sample_accepted`。

### H05. 异常退出后的扫描与恢复

**当前问题与依据**

启动录制时先写入 `recording_status=recording`，正常结束再更新。当前未发现启动后专门扫描、验证和处理遗留录制的流程。现有 `flush()` 周期不等于断电持久化承诺；最终 `fsync()` 也只能在实际执行成功时提供保证。

**建议逻辑**

- 启动后或用户主动检查时，扫描遗留 `recording/finalizing`、缺失元数据、缺失 CSV、空文件和异常尾行。
- 自动扫描只读；不得把一个仍由其他活动进程持有的录制当作崩溃遗留文件，需有明确的录制所有权/活动状态确认方式。
- 恢复只恢复可验证的完整行，不伪造结束时间、丢失帧或动作完成事实；原文件保留，修复内容写入独立恢复文件或保留明确备份。
- 对无法确认动作完整性的样本设为恢复后待复核/不合格，不能自动变成有效训练样本。
- 故障后重建索引时生成异常清单，列出目录和原因；不以“索引中没有这一行”代替错误报告。
- 保存失败的样本编号继续保留，避免重试覆盖残留证据。

**验收条件**

- 强制中断后重启，能够找到遗留样本并报告其状态。
- 半行 CSV、无 meta、无 raw、损坏 JSON 均有明确处理结果。
- 恢复和重试不覆盖已完成数据，不将未知质量默认为通过。

**代码入口**：`RawSampleRecorder.start/_write_meta`，`DatasetStore.rebuild_index`，主窗口初始化与专用检查/恢复入口。

## 5. 中优先级：完善实验复现与采集效率

### M01. 无接触参考与显示基线说明

**现状**：原始 CSV 未扣基线；现有 `CalibrationSnapshot` 保存开始时可用的运行基线，但运行基线受滤波开关、归一化模式和慢跟踪影响，部分点位还可能未就绪。慢跟踪在持续握持/拥抱时会吸收一部分持续响应。这属于显示及基线参考含义问题，不代表原始 CSV 被衰减。

**建议**：

- 在流程中明确记录动作前后的无接触参考区间，区间长度通过试采确定，不统一硬编码为固定秒数。
- 保存原始参考片段的时间范围与确认方式，离线按有效点逐点计算基线。
- 当前运行基线作为可选辅助快照，附带来源、是否滤波、就绪程度和坐标顺序；不要默认它等价于未滤波原始 ADC 的无接触基线。
- 需要稳定观察长接触时，可以增加“录制期间固定显示基线”；若仍允许录制中切换滤波或重置显示基线，应记录事件并解释画面变化。
- 原始采集不强依赖显示标定完成；离线扣基线前转换为有符号或浮点类型。

**验收**：同一份原始样本可以采用不同离线基线算法重算；显示模式切换不改变原始文件，参考区间可定位。

### M02. 历史样本回放、复核及动作区间标注

**现状**：当前主要通过 `last_sample` 审核最近一条；尚无完整历史样本回放入口。`annotation.action_start_s/action_end_s` 已预留，但仍为空。

**建议**：

- 按受试者、场次、动作和次数选择历史样本；读取该样本引用的布局、掩码及类别版本。
- 显示原始 CSV 热力图、选点时间曲线、录制区间和接收异常区间。
- 支持标记实际接触开始/结束；录制按钮时间保留为录制边界，不能自动当成接触边界。
- 在回放中复核有效/作废和说明；记录审核时间及修改历史。
- 异步块按各自时间展示，超过允许时间差显示缺失，不能无限保持旧值掩盖断流。

**验收**：可从磁盘重放一次真实保存样本，恢复其原方向与数值；可复核历史而非只能复核最近一条。

### M03. 采集进度与有效样本统计

**建议**：按“受试者 × 场次 × 动作”显示已完成、有效、待审核、异常和作废数量；支持配置采集目标，缺项提示基于有效样本数。

统计必须结合版本解释动作，不能把 `actions_v1` 的按压混入 `actions_v2` 的握持。回收数据不计入正式数量，恢复后刷新。

**验收**：新增、审核、作废、回收、恢复后数量一致；1000 条总文件不被误认为 1000 条有效独立动作。

### M04. 实验条件、协议和质量规则追溯

**现状**：场次已记录串口配置、布局、类别、皮肤块范围等基础信息；接收方式可以自动识别，但场次中的选择值可能仍为 `auto`。当前样本质量统计未完整关联录制期间解析异常增量。

**建议**：

- 保存请求模式和实际识别模式，保留软件版本、关键规则版本以及必要的配置摘要。
- 记录本段起止间的解析错误计数变化；作为观测异常，不直接换算为准确丢帧数。
- 记录皮肤安装/更换、动作接触部位、操作者、实验备注等必要条件，先使用现有场次字段，再扩展确有用途的内容。
- 明确一次轻拍与连续多次轻拍的执行约定；握持/拥抱保持时长由试采确定。
- 训练划分按目标保留受试者/场次独立性；同一录制切片不能随机分散到训练与测试两边。

**验收**：脱离当前软件界面，仅靠样本及引用文件能够说明采集条件和质量判定依据。

### M05. 批量性能与索引异常报告

**现状**：每次结束和审核都遍历样本元数据重建索引；`rebuild_index()` 遇到部分坏元数据会跳过，当前界面未提供完整异常报告。随着样本数增长，每次操作的成本可能增加，但本次没有做千条规模基准，不能认定当前已经卡顿。

**建议**：

- 先测 100、1000、5000 条时的结束、审核、列表刷新和索引重建耗时，再决定是否改为增量更新或后台重建。
- 保留全量重建能力，把元数据作为事实来源，索引作为可再生成清单。
- 所有跳过项形成可查看的报告；不因某条损坏就阻断其他正常样本，也不静默隐藏。
- 测量预期最高接收负载下的队列峰值、实际写入速度和 GUI 响应；根据实测确定队列容量与批量写入策略。

**验收**：达到目标数据规模时操作耗时可测、异常可见；性能优化不能导致接纳边界变化或中间帧漏记。

### M06. 回收恢复边界与备份校验

**现状**：已实现整目录回收、原路径恢复、同名拒绝覆盖和索引失败回滚，并有测试。还需覆盖单个损坏 `deleted.json` 不影响其他回收项、嵌套回收的恢复顺序、移动或索引提交时强制退出等边界。

**建议**：

- 回收列表对坏清单逐项报告，继续展示其他可恢复项。
- 移动/恢复操作保存可核查状态，异常退出后识别“目录已移动但索引未刷新”等情况。
- 备份整套数据和被引用配置，包括标签各版本、布局、场次、原始文件及审核信息。
- 增加只读校验：引用是否存在、CSV 是否可解析、尺寸/列数是否一致，必要时保存文件摘要。
- 定期用副本完成一次恢复演练；明确本地 `_trash` 是恢复误删的机制，同盘损坏仍需要独立备份。

**验收**：迁移副本后可重建索引、解析配置和回放样本；一条坏回收记录不阻断所有恢复操作。

## 6. 低优先级：核心流程稳定后的扩展

### L01. 倒计时、快捷键和重复采集辅助

增加可配置准备提示、开始/结束快捷键及重复次数提醒。自动停止仅在动作协议明确后启用。收尾未完成时快捷键不能绕过锁定，不能创建跨样本数据。

### L02. 非破坏性数值健康提示

只对有效位置统计接近量程边界的比例、长时间恒定和异常跳变，先作为提示。持续握持本身可能接近恒定，合法读数也可能为 0 或 4095，因此不得仅凭这些特征自动作废、裁剪或修改掩码。需要按真实皮肤和采集模式验证提示规则。

### L03. 硬件帧序号、采样时间与校验扩展

后续固件可考虑提供每块帧序号、设备采样时间以及协议校验。主机接收时间不等于硬件采样时间，多块也不能天然视为同步采样。

此项涉及板端与协议共同修改，当前默认列为低优先级。如果后续模型明确要求精确多块同步或准确丢帧统计，应单独提升优先级；已有 CSV 的时间含义不能悄悄改变。

### L04. 文档一致性与界面细节

- 清理 README 中“训练数据录制仍处于设计阶段，尚未集成”的旧描述，与 `collection` 实际功能保持一致。
- 明确区分显示原始 ADC、显示基线处理结果和磁盘原始数据。
- 为禁用的主操作按钮提供清楚的视觉状态；新增完整性、收尾状态后核查小窗口布局和提示可读性。
- 代码注释重点解释时间口径、录制状态转换、并发边界和异常回滚，延续必要注释要求。

## 7. 建议实施顺序与阶段交付

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 第一阶段：完整性闭环 | H01、H02，并同步加入 H04 的状态字段与底层审核约束 | 异常样本能识别、说明原因且不会被放行 |
| 第二阶段：故障收尾与恢复 | H03、H05，完成 H04 的索引及旧数据迁移 | 写盘未结束不能重开，异常退出可发现和恢复 |
| 第三阶段：小规模试采复核 | M01～M04 | 原始样本可回放、参考区间可定位、有效数量可统计 |
| 第四阶段：规模验证与管理 | M05、M06，再按需要实施低优先级项 | 数据规模扩大后性能、校验和恢复可验证 |

第一阶段是最先应完成的具体工作。H03 的线程未结束就清除引用问题也应尽早修复，不能等待大量样本采集后再处理。

建议按实际数据流组织职责：

```text
串口解析
  → 原始块 + 主机接收时间
  → 冻结的本次录制计划
  → 逐块完整性统计 + 有界写盘队列
  → 后台收尾与文件验证
  → 录制状态 / 质量状态 / 人工审核
  → 可重建的索引与训练筛选

同一原始块
  → 独立的显示滤波、基线和归一化
  → 热力图
```

质量统计尽量使用可独立验证的模块，GUI 展示其结果；不要在 `MainWindow` 中继续堆积所有判定逻辑。第一版无需引入新的存储格式或数据库。

## 8. 最小验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 所有参与块正常更新，正常结束 | 文件完成、质量通过，等待人工确认动作 |
| 某必需块开始前离线或缓存过旧 | 不进入正式录制，提示对应编号 |
| 录制 10 秒只收到一帧 | 质量失败，不得设为正式有效 |
| 某块首帧迟到、中途断流或提前停更 | 分别记录区间并按本次阈值判级 |
| 某块整段未出现 | 质量失败，其他块数据保留 |
| 全部块曾出现后串口异常断开 | 异常结束，不得按正常动作完成处理 |
| 尺寸改变、布局外块到达 | 按冻结计划拒绝不兼容行并记录原因，不临时改列 |
| 写盘队列满、磁盘报错、收尾超时 | 提示故障、保留已有内容，未真正收尾前不允许重开或回收 |
| 进程强制退出后重启 | 可发现遗留文件，不自动当成有效样本 |
| 同一动作数字编号来自不同标签版本 | 正确区分语义，不按裸编号混合 |
| 对不完整样本直接调用“设为有效”接口 | 底层拒绝，不能仅依赖按钮禁用 |
| 切换显示滤波或基线设置 | 原始 ADC 内容和通道顺序不变，显示变化有解释 |
| 旧元数据缺新质量字段 | 标为未知/待验证，保留原文件 |
| 回收、恢复、索引写入失败 | 原始值不变，状态可回滚或可恢复，索引与文件对应 |
